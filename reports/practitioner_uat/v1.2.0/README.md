## 실행 순서

1. `릴리스_체크` 시트에서 버전, 커밋, Graph build ID와 해시가 현재 앱과 일치하는지 확인한다.
2. `실행큐_75` 시트의 순서대로 새 채팅에서 각 질문을 실행한다.
3. P0 문항은 1·2회차가 각각 별도 행으로 준비되어 있으므로 서로 다른 새 채팅에서 실행한다.
4. 답변 전문, 출처, 점수, 판정, 결함 분류와 메모를 행별로 기록한다.
5. `대화_연속성` 시트의 8개 시나리오는 같은 채팅 안에서 순서대로 실행한다.
6. `온톨로지_경계` 시트에서 승인 6개와 정확한 17개 별칭이 검색되는지, 거절 10개와 금지 표현이 노출되지 않는지 확인한다.
7. `실행_대시보드`의 릴리스 게이트 결과를 확인한다.

## 합격 기준

- P0 문항: 모든 실행 점수 4점 이상
- 전체 실행 평균: 4.3점 이상
- 1~2점 결함: 0건
- 온톨로지 경계 10개: 전부 PASS
- 대화 연속성 8개: 전부 PASS
- 근거가 없거나 모호한 경우에는 추정 결론 대신 확인 질문 또는 보류 안내가 나와야 한다.
- 수술종수, 수가코드, 진단코드, 계산 결과가 서로 다른 의도로 혼동되지 않아야 한다.

하나라도 실패하면 릴리스 자체를 즉시 되돌리기보다 해당 문항의 검색 경로, Graph 근거, 문서 출처, 대화 상태를 먼저 분류한다. 계산 룰 변경은 별도 실무 승인 없이는 수행하지 않는다.

## 시트 설명

- `릴리스_체크`: 실행 대상 버전과 데이터 해시 확인
- `판정_기준`: 1~5점 기준과 결함 분류
- `실행큐_75`: 64개 고유 문항을 P0 반복 실행까지 포함해 75개 실행 행으로 펼친 기록란
- `원본_76`: 두 평가자료의 원본 행 보존
- `대화_연속성`: 후속 질문 및 계산에서 일반 질의로 이어지는 흐름 검증
- `온톨로지_경계`: 승인·거절·금지 표현 검증
- `실행_대시보드`: 진행률과 릴리스 게이트 집계

## 보류된 항목

실제 DGX 데스크톱 브라우저에서의 물리적 GUI UAT는 사용자 요청에 따라 이번 작업의 남은 항목으로 보류한다. 이 문서는 테스트 설계와 실행 준비 완료를 의미하며, 실무자 실행 결과 자체를 의미하지 않는다.

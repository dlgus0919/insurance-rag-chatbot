# 199. 운전자보험 조항 세부 질의 RAG 패치 보고서

## 배경

운전자보험 관련 테스트 질의에서 다음 문제가 확인되었다.

- `특정 외상성 뇌출혈 진단비(최초 1회한) 특별약관에서 진단확정 기준을 알려줘`
  - 실제 `자사_SOL운전자 p.71`에 진단확정 기준이 검색되었으나, 모델 답변은 `제공된 컨텍스트에 포함되어 있지 않다`고 응답했다.
- `자동차사고 부상치료지원금 담보를 청구하려 해. 필요한 서류를 알려줘.`
  - 실제 답은 `자사_SOL운전자 p.74 제3조(보험금의 청구)`에 있으나, 일반 청구서류 조항과 실손/표준약관 후보가 앞서며 해당 조항이 상위 후보에 안정적으로 노출되지 않았다.
- `가족일상생활배상책임 특별약관에서 자기부담금을 설명해줘`
  - 자기부담금 근거 문구는 원천 문서에 있으나, 동일/유사 조항 후보와 중복 source가 섞이며 답변이 근거를 제대로 활용하지 못했다.

## 원인

이번 이슈는 원문 또는 인덱스 부재가 아니라 검색/생성 연결부의 문제였다.

1. 조항 세부 질의가 `general_explanation` 또는 일반 보상 판단 질의로 처리되었다.
   - `진단확정`, `청구서류`, `자기부담금`은 의미 검색보다 조항 표제어와 BM25의 영향이 큰 질의다.
2. 담보명이 있는 질문에서도 일반 조항 표제어가 더 강하게 작동했다.
   - 예: `청구서류`가 건강보험의 일반 청구서류 조항을 먼저 끌어오고, `자동차사고 부상치료지원금` 담보 조항을 뒤로 밀었다.
3. 동일 문서/페이지/본문 청크가 서로 다른 chunk id로 반복되어 top-k와 UI 참고 영역을 소모했다.
4. 근거가 top hit에 있더라도 LLM이 보수적 system prompt를 오판하면 `확인되지 않습니다` 답변이 그대로 통과했다.

## 패치 내용

### 1. 조항 세부 intent 추가

`src/rag/search_intent.py`에 `clause_detail_lookup`을 추가했다.

감지 대상:

- 진단확정/확정기준/진단기준
- 필요서류/청구서류/제출서류/구비서류
- 자기부담금/자기부담

담보/특약/특별약관/진단비/지원금 또는 보상 판단 단서와 함께 나오면 BM25 비중을 높이고 후보 수를 확장한다.

### 2. 상품 문서 내부 조항 보강 검색

`src/rag/pipeline.py`에 조항 세부 보강 검색을 추가했다.

- 기존 검색 후보에서 우세한 상품 문서를 찾는다.
- 질문의 핵심 담보명/항목명을 anchor term으로 추출한다.
- 같은 상품 문서 안에서 다음 조항 표제어를 추가 검색한다.
  - `보험금의 청구`, `청구서`, `사고증명서`, `신분증`
  - `정의 및 진단확정`, `병력`, `신경학적 검진`, `CT`, `MRI`
  - `자기부담금`, `보험금 등의 지급한도`
- 후보를 anchor term 점수로 재정렬해 일반 청구서류 조항보다 질문 담보명이 포함된 조항을 우선한다.

이 방식은 `자동차사고 부상치료지원금` 같은 특정 담보명을 코드에 직접 박는 것이 아니라, 질문에 포함된 담보명과 문서 내부 조항 표제어를 조합해 작동한다.

### 3. 중복 검색 후보 및 UI source 중복 제거

- `src/rag/pipeline.py`
  - 같은 문서/페이지/section/본문 prefix가 반복되는 hit를 병합 단계에서 제거한다.
- `src/api/rag_service.py`
  - UI `참고` source list도 문서/페이지/snippet 기준으로 중복 제거한다.

### 4. deterministic 조항 세부 답변 보강

`src/rag/pipeline.py`의 deterministic guard에 조항 세부 요약을 추가했다.

- 검색된 청크 안에 실제 조항 표제어와 관련 문구가 있을 때만 작동한다.
- LLM 호출 전에 짧은 근거 요약을 생성해, 모델이 근거를 놓치고 `컨텍스트 없음`으로 답하는 오류를 차단한다.
- 문서에 없는 내용을 생성하지 않고, 검색된 줄만 요약한다.

## 남은 한계

- 질문에 상품명이 명시되지 않고 동일 특별약관이 여러 상품에 반복 수록된 경우, 어느 상품 기준인지 완전히 확정할 수 없다.
- 이 경우 현재 로직은 질문 담보명과 조항 표제어가 가장 강하게 맞는 근거를 우선한다.
- 향후에는 실무자 승인형 ontology 또는 상품/담보 선택 UI와 연결해 `어느 상품 기준인지`를 명시적으로 받을 수 있다.

## 결론

이번 문제는 온톨로지 실무자 승인 워크플로우와 독립적으로 해결 가능한 RAG 검색/생성 연결부 결함이었다. 패치 후 운전자보험 조항 세부 질의 3건은 모두 조항 세부 intent로 분기되고, 관련 원문 조항을 상위 검색 후보와 deterministic 답변에 반영한다.

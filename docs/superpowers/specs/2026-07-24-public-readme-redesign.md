# 외부 공개·포트폴리오 README 개편 설계

## 1. 목적

`insurance-rag-chatbot` 저장소의 첫 화면을 외부 공개·포트폴리오 방문자 기준으로 다시 구성한다. 방문자는 약 3분 안에 프로젝트가 해결하는 문제, 실제 구현 범위, 핵심 안전 원칙과 기술 구조를 이해할 수 있어야 한다. 개발자와 유지보수 담당자는 같은 문서의 후반부에서 재현 범위, 저장소 구조, 검증 명령과 상세 문서 진입점을 찾을 수 있어야 한다.

## 2. 현재 기준

- 원격 기준 커밋: `89bc12e5f5f2ab029d003ac7ff37e9960de74172`
- 안정 릴리스 태그: `v1.2.b`
- 프론트엔드 표시 버전: `1.2.0.b`
- 현재 운영 UI: FastAPI API와 정적 SPA
- 기본 로컬 LLM 경로: SGLang과 `qwen3-next-80b-a3b-instruct-fp8`
- 선택 가능한 경량 모델: `gpt-oss-20b`
- 기준 하드웨어: DGX Spark ARM64 Linux
- 최신 `master`: 안정 태그 이후 GraphDB 안전 기준 보조 파일 재발 방지 패치 포함

안정 태그, UI 표시 버전과 최신 `master`는 서로 다른 개념이므로 README에서 하나의 버전처럼 합쳐 쓰지 않는다.

## 3. 대상 독자

1차 독자는 외부 공개·포트폴리오 방문자다. 보험 업무 담당자, 평가자, 기술 면접관과 AI/RAG 개발자가 별도 사전 지식 없이 읽는 상황을 가정한다.

2차 독자는 저장소를 인수하는 개발자와 운영 담당자다. 내부 절대경로, 계정, 비밀값과 운영 데이터는 공개하지 않고, 공개 가능한 문서와 명령만 제공한다.

## 4. 핵심 메시지

- 이 프로젝트는 보험금 지급을 자동 확정하는 챗봇이 아니라 원문 근거, 승인된 지식과 결정적 계산 경로를 제공하는 실무 지원 시스템이다.
- 일반 질의는 Hybrid RAG, GraphDB와 로컬 LLM을 결합한다.
- 보험금 계산은 LLM이 금액을 생성하는 방식이 아니라 승인된 활성 룰을 결정적 계산 엔진이 실행하는 방식이다.
- 신규 온톨로지와 계산 룰은 후보, 검토, 승인과 운영 반영 단계를 거친다.
- 표준 운영은 DGX Spark에서 로컬로 동작하며 OpenAI·CLOVA 같은 외부 API를 요구하지 않는다.
- 저장소에는 원본 보험 문서, 운영 인덱스, 모델, 계정, 대화 기록과 `.env`가 포함되지 않으므로 저장소만 내려받아 완전 운영 환경을 재현할 수는 없다.

## 6. 시각 설계

- 저장소에 추적된 `assets/logo.svg`만 첫 화면에 사용한다.
- 추적되지 않은 제품 화면 캡처를 README에서 참조하지 않는다.
- Mermaid 다이어그램 두 개를 사용한다.
  - 일반 질의와 근거 생성 아키텍처
  - 승인 기반 지식 운영과 계산 경로
- 기능 목록과 기술 구성은 짧은 표와 불릿을 혼합해 스캔 가능하게 만든다.
- 지나친 배지, 이모지와 홍보 문구를 사용하지 않는다.

## 7. 공개 범위

### 포함

- 공개 저장소에서 직접 확인 가능한 기능과 구조
- `v1.2.b`, `1.2.0.b`, 최신 `master`의 역할 차이
- FastAPI, SPA, BM25, Chroma, RRF, reranker, GraphDB, RuleRegistry, SGLang과 Qwen의 역할
- 문서·모델·인덱스가 별도 자산이라는 재현 경계
- 공개된 테스트 명령과 선별 문서 링크

### 제외

- DGX 내부 계정, 비밀번호, 비밀 환경값
- 사용자·대화·감사 로그
- 사내 절대경로를 전제로 한 실행 예시
- 원문 PDF 제목 목록과 비공개 데이터 세부사항
- 존재하지 않는 라이선스 또는 배포 권한
- 과거 Streamlit 경로를 현재 운영 경로처럼 보이게 하는 설명
- 신규 스캔 문서 OCR을 현재 지식 확장 경로로 안내하는 설명

## 8. 실행 안내 원칙

실행 안내는 두 수준으로 나눈다.

### 저장소 수준 검토

- Python 3.11 이상
- 가상환경 생성
- `requirements.txt` 설치
- `.env.example`을 로컬 `.env`로 복사
- 단위·통합 테스트와 Playwright E2E 명령

### 완전 운영

아래 별도 자산이 있어야 한다.

- 디지털 텍스트 원문과 canonical chunk
- BM25·Chroma 검색 인덱스
- 승인된 온톨로지·GraphDB·활성 계산 룰
- 임베딩·reranker·LLM 모델
- 운영 환경 설정과 초기 관리자 계정

README의 개발 명령은 코드 검토와 테스트의 출발점이다. 완전한 보험 답변 품질을 보장하는 설치 명령으로 표현하지 않는다.

## 9. 검증 기준

- Markdown 코드 펜스가 짝을 이룬다.
- 모든 상대 링크가 저장소의 실제 파일을 가리킨다.
- README에 `v1.2.0`을 현재 후보 릴리스로 표현하는 오래된 문구가 남지 않는다.
- 안정 태그 `v1.2.b`, UI `1.2.0.b`, 최신 `master`를 구분한다.
- `localhost:18080`과 SGLang `127.0.0.1:30000`은 공개 가능한 기본값으로만 설명한다.
- FastAPI+SPA를 현재 기준으로, Streamlit을 역사적 경로로 표시한다.
- 외부 API가 표준 기동에 필요하다고 오해할 문구를 제거한다.
- 저장소에 없는 원본 자료·모델·인덱스가 포함된 것처럼 표현하지 않는다.
- `git diff --check`가 통과한다.
- 원격 `master`가 작업 기준 커밋에서 변경되지 않았음을 push 직전에 재검증한다.

## 10. 전달 방식

- 현재 오염된 로컬 작업공간은 수정하지 않는다.
- 최신 원격 `master`에서 만든 격리 브랜치에서 README와 본 설계·계획 문서만 변경한다.
- 검증 후 의도한 파일만 커밋한다.
- 원격 동시 변경이 없을 때만 `master`로 업로드한다.

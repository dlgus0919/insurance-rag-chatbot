# 5세대 산정특례 및 그룹 합산 공제 보완 설계

## 목적

5세대 실손 보험금 계산에서 산정특례 여부와 3대비급여/MRI-MRA 분기, 동일 공제 그룹 합산 공제를 명확히 처리한다.

이번 설계는 `claim_calculation_special_case_and_group_deductible_spec_20260709.md`를 기준으로 하며, 000번 규칙을 따른다.

- 세대별 보상률, 공제금, 한도 등 보험 지식값은 active rule manifest와 실무자 승인 흐름을 우선한다.
- 계산 엔진은 승인된 rule과 입력값을 해석해 계산한다.
- LLM은 지급 판단, 공제율, 한도, 보상률을 생성하지 않는다.
- 원문 근거와 승인 없는 계산 rule은 자동 적용하지 않는다.

## 핵심 결정

산정특례 여부는 항목별 값이 아니라 계산 케이스 단위의 단일 선택값이다.

예를 들어 하나의 십자인대 파열 진단으로 발생한 100여 개 항목을 한 번에 계산하는 경우, `산정특례 미적용`을 한 번 선택하면 전체 항목에 동일하게 적용한다. 특정 항목만 산정특례 적용으로 계산하는 UI나 API 계약은 이번 범위에 넣지 않는다.

입력값:

- `unknown`: 모름
- `applied`: 산정특례 적용
- `not_applied`: 산정특례 미적용

UI 표시:

- 모름
- 적용
- 미적용

## 범위

포함:

- 보험금 계산 케이스 입력에 산정특례 여부 추가
- 5세대 3대비급여/비급여 자기공명영상진단 분기
- 산정특례 미적용 또는 모름 상태에서 위험한 3대비급여 자동 계산 차단
- 동일 공제 그룹 합산 후 1회 공제
- 관리자 지식 확장 탭의 제한된 rule 후보 추출/검토/승인 흐름
- 조건부 재계산 흐름에서 산정특례 상태 확인
- 회귀 테스트와 계산 결과 검증

제외:

- 전체 약관에서 모든 계산 rule을 일반화 추출하는 기능
- 항목별 산정특례 선택
- 산정특례 여부를 LLM이 추정하는 기능
- OCR 원문에서 산정특례 여부를 자동 판독하는 기능
- active rule manifest에 없는 임시 rule을 계산에 사용하는 기능

## Rule 후보 범위

이번 rule 후보 자동 추출/승인 UI는 첨부 명세의 5세대 보완 rule에 한정한다.

대상 후보:

- 5세대 산정특례 적용 시 3대비급여 공제/보상 rule
- 5세대 산정특례 미적용 시 도수치료, 체외충격파, 증식치료, 주사료 계열 자동 보상 차단 rule
- 5세대 산정특례 미적용 시 MRI/MRA를 `비급여자기공명영상진단`으로 계산하는 rule
- MRI/MRA의 5세대 공제/한도 rule

기존 승인 rule은 가능한 한 유지한다. 같은 `rule_id`를 수정해야 하는 경우에는 신규 rule처럼 덮어쓰지 않고, 실무자가 수정/승인한 변경 이력으로 남긴다.

## 데이터 모델

`ClaimCaseContext`에 케이스 단위 필드를 추가한다.

```json
{
  "policy_generation": "5th",
  "visit_type": "hospitalization",
  "special_calculation_status": "not_applied"
}
```

전달 경로:

- 프론트엔드 보험금 계산 form
- API request schema
- `ClaimCaseContext`
- 계산 pipeline
- claim snapshot
- 조건부 재계산 입력 복원

`special_calculation_status`가 없으면 `unknown`으로 해석한다.

## 계산 로직

### 세대 분기

5세대가 아니면 기존 계산 흐름을 유지한다.

5세대인 경우에만 산정특례 상태를 본다.

### 산정특례 적용

`special_calculation_status = applied`이면 3대비급여 항목을 5세대 산정특례 적용 rule로 계산한다.

도수치료, 체외충격파, 증식치료, 주사료, MRI/MRA가 3대비급여로 분류될 수 있다.

### 산정특례 미적용

`special_calculation_status = not_applied`이면 다음처럼 처리한다.

- MRI/MRA: `비급여자기공명영상진단` rule로 계산한다.
- 도수치료, 체외충격파, 증식치료, 일반 주사료 계열: 예상 지급액 0원, 추가 확인 또는 보상 제외 사유로 표시한다.
- 일반 비급여와 급여 본인부담: 기존 승인 rule에 따라 계산한다.

### 산정특례 모름

`special_calculation_status = unknown`이면 위험한 3대비급여 자동 계산을 하지 않는다.

- MRI/MRA, 도수치료, 체외충격파, 증식치료, 주사료 계열은 추가 확인 대상으로 보낸다.
- 사용자에게 산정특례 적용 여부를 확인하라는 안내를 표시한다.

## 그룹 합산 공제

그룹 합산 공제는 계산 엔진 규칙으로 고정한다.

동일 공제 그룹의 여러 항목은 항목별로 공제하지 않고, 그룹 합계에 대해 한 번 공제한다. 이후 산출된 지급액과 공제액은 항목 금액 비율에 따라 line result에 배분한다.

그룹 key:

```text
policy_generation
visit_type
facility_grade
special_calculation_status
deductible_group
```

`deductible_group` 예시:

- benefit_group
- general_nonpay_group
- three_major_nonpay_group
- mri_mra_group
- prescription_group

그룹 합산 공제는 나중에 바뀔 가능성이 낮은 계산 방식이므로 코드 수준에 둔다. 다만 코드 주석에 “보험 지식값이 아니라 동일 공제 단위 합산 후 1회 공제하는 계산 엔진 규칙”임을 명시한다.

## 관리자 UI

지식 확장 탭의 rule 후보 영역을 재사용한다.

이번 후보는 “5세대 산정특례/3대비급여/MRI-MRA 보완 후보”로 구분해 표시한다.

실무자에게 보여줄 정보:

- 후보명
- 적용 세대: 5세대
- 산정특례 상태: 적용/미적용/모름
- 적용 대상: 3대비급여, 비급여 자기공명영상진단, 보상 차단 대상
- 제안 rule 값
- 원문 근거 chunk
- 현재 active rule과의 차이
- 승인 시 영향

후보 설명은 실무자 표현을 우선한다. `unknown`, `outpatient`, `three_major_nonpay` 같은 내부 값은 보조 정보로만 표시한다.

## 조건부 재계산

이전 계산 결과를 바탕으로 일반 질의에서 재계산을 요청할 때도 산정특례 상태를 유지한다.

예:

- “이 항목을 3대비급여로 보상한다면?”
- “MRI는 보상 대상으로 보면 얼마인가요?”
- “산정특례 미적용이면 다시 계산해 주세요.”

처리 원칙:

- 기존 claim snapshot의 `special_calculation_status`를 우선 사용한다.
- 사용자가 새 산정특례 상태를 명시하면 새 상태로 재계산한다.
- 5세대인데 상태가 모호하면 계산하지 않고 확인 질문을 반환한다.
- LLM이 산정특례 적용 여부를 임의 확정하지 않는다.

## 오류 처리

- 산정특례 상태 누락: `unknown`으로 처리하고 위험 항목은 추가 확인 대상으로 보낸다.
- 5세대 산정특례 미적용 상태에서 3대비급여 자동 계산 요청: 차단하고 이유를 표시한다.
- rule 후보에 원문 근거가 없으면 승인 불가로 표시한다.
- active rule manifest 검증 실패 시 병합하지 않는다.
- 같은 rule ID 충돌은 실무자 수정 흐름으로 안내한다.

## 테스트

필수 테스트:

- 5세대 + 산정특례 미적용 + 도수치료: 예상 지급액 0원, 추가 확인 또는 보상 제외 사유 표시
- 5세대 + 산정특례 미적용 + 일반 비급여 주사료: 예상 지급액 0원
- 5세대 + 산정특례 미적용 + MRI/MRA: `비급여자기공명영상진단` rule로 계산
- 5세대 + 산정특례 적용 + 도수치료/주사료/MRI: 3대비급여 rule로 계산
- 5세대 + 산정특례 모름 + 3대비급여 후보: 자동 계산하지 않고 확인 요청
- 동일 공제 그룹 2개 이상 항목: 그룹 합계에 대해 공제 1회 적용
- claim snapshot 저장/복원 시 산정특례 상태 유지
- 조건부 재계산 시 산정특례 상태 유지 또는 명시 변경 반영
- 관리자 rule 후보 UI에서 내부 코드값 대신 실무자 표현 표시

기존 테스트 수정:

- 5세대 3대비급여가 항상 50%로 계산된다는 전제의 테스트는 새 명세에 맞게 변경한다.
- MRI/MRA 5세대 계산 테스트는 산정특례 상태별 기대값을 분리한다.

## 완료 기준

- 실무자가 계산 요청 1회마다 산정특례 여부를 한 번만 선택할 수 있다.
- 5세대 산정특례 미적용 케이스에서 3대비급여를 잘못 보상하지 않는다.
- MRI/MRA는 산정특례 미적용 상태에서 별도 rule로 계산된다.
- 동일 공제 그룹 항목은 항목별 공제가 아니라 그룹 합산 공제로 계산된다.
- 새 rule 후보는 첨부 명세 범위 안에서만 생성된다.
- 승인된 active rule과 source evidence가 보존된다.
- 테스트와 self-inspection에서 000번 규칙 위반이 발견되지 않는다.

## 남은 위험

- 첨부 명세의 source chunk와 현재 DGX active index가 어긋나면 후보 근거 표시가 실패할 수 있다.
- 기존 active rule 중 5세대 3대비급여 rule ID를 그대로 수정할지, 새 rule ID로 분리할지는 구현 전 manifest 상태를 다시 확인해야 한다.
- 그룹 배분 시 원 단위 반올림 오차가 생길 수 있으므로 합계 보정 테스트가 필요하다.
- 산정특례 상태를 잘못 선택하면 전체 케이스 계산이 달라지므로 UI 안내가 명확해야 한다.

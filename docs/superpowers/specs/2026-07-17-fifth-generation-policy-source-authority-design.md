# 5세대 약관 출처 권위 및 재인제스트 안전성 설계

## 1. 목적

5세대 실손을 선택했을 때 실제로는 등록·색인된 5세대 표준약관의 직접 조항을 사용하면서도 화면에 `등록된 5세대 자사 상품 약관이 없으므로 표준약관을 참고 기준으로 안내합니다`라고 표시되는 혼동을 제거한다. 동시에 향후 전체 인제스트에서 문서 세대 메타데이터가 유실되어 5세대 검색 자체가 실패할 수 있는 회귀 위험을 차단한다.

이번 변경은 현재 인덱스를 재구축하지 않는 제한적 안전 패치다. 표준약관 전체 856개 청크의 구간별 세대 재분류는 별도 승인 과제로 남긴다.

## 2. 확인된 현재 상태

### 2.1 원본과 색인 데이터

- DGX 원본 폴더에는 5세대 표준약관 PDF와 4세대 신한EZ 자사 실손약관 PDF가 각각 존재한다.
- 현재 처리 데이터에는 자사 약관 384개 청크가 `policy_generation=4th`, `is_own_company=true`로 존재한다.
- 표준약관 856개 청크가 `policy_generation=5th`로 존재하고, 탈모 직접 조항 5개가 검색된다.
- 탈모의 5세대 직접 근거는 `표준약관_ch_005453`으로 고정되어 있으며 페이지 범위는 p.296–309다.

따라서 앱샷의 최신 5세대 답변은 검색 실패가 아니다. 5세대 표준약관을 올바르게 찾은 뒤, 별도의 정적 안내 문구를 덧붙인 결과다.

### 2.2 문구가 잘못 나오는 경로

`src/rag/source_grounded_answers.py::_authority_note()`는 직접 근거 중 `is_own_company=true`가 없으면 온톨로지 프로필의 `standard_reference_note`를 그대로 반환한다. `data/ontology/concepts.json`의 해당 값은 현재 데이터 인벤토리를 런타임에 확인하지 않고 `등록된 5세대 자사 상품 약관이 없다`고 단정한다.

이 구조에는 다음 결점이 있다.

1. 표준약관이 실제로 등록되어 있다는 사실보다 자사약관 부재 문장이 앞서 사용자에게 문서 미등록처럼 읽힌다.
2. 이후 자사 5세대 약관이 추가되어도 정적 문구가 남을 수 있다.
3. 자사약관과 표준약관 청크가 함께 선택될 때 하나의 출처만 사용한 것처럼 표시할 수 있다.
4. 현재 활성 온톨로지 파일에 과거 문구가 남아 있으면 기본 파일만 수정해도 운영 답변에 계속 노출될 수 있다.

### 2.3 재인제스트 회귀 위험

`PdfSource.policy_generation`은 과거 추가되었으나 현재 `src/config.py`에서 제거되어 있다. 현재 인덱스에는 기존 메타데이터가 남아 있어 검색이 동작하지만, 지금 설정으로 전체 인제스트를 다시 실행하면 새 청크에 세대 정보가 들어가지 않을 수 있다. 그 결과 세대 필터가 5세대 표준약관 청크를 제외하여 최신 답변이 다시 `공식 문서가 제공되지 않았다`는 경로로 퇴행할 수 있다.

## 3. 검토한 접근법

### A. 표시 문구만 교체

온톨로지의 한 문장만 중립 문구로 바꾼다.

- 장점: 변경량이 가장 작다.
- 결점: 자사·표준·혼합 출처를 구분하지 못하며, 활성 온톨로지의 낡은 값과 재인제스트 세대 유실 위험이 남는다.

### B. 선택 청크 메타데이터 기반 권위 표시 + 설정 복구 — 채택

최종 선택된 직접 근거 청크에서 자사/표준 여부를 계산해 문구를 만들고, `PdfSource.policy_generation`을 복구한다. 현재 인덱스는 재구축하지 않는다.

- 장점: 현재 증상과 다음 인제스트 위험을 함께 해결한다.
- 장점: 향후 자사 5세대 약관이 추가되어도 선택된 근거에 따라 문구가 자동으로 바뀐다.
- 장점: 색인·GraphDB·운영 대화 DB를 건드리지 않아 배포 위험이 낮다.
- 결점: 현재 표준약관 전체가 5세대로 일괄 태깅된 데이터 모델은 그대로 남는다.

### C. 표준약관 구간별 재분류와 전체 재인덱싱

표준약관 PDF의 섹션마다 세대·상품 유형을 다시 분류하고 BM25, Chroma, GraphDB를 모두 재구축한다.

- 장점: 장기 데이터 정확도가 가장 높다.
- 결점: 856개 청크와 모든 검색 인덱스의 결과 순위를 바꾸며, 운영 검증 범위가 크게 증가한다.
- 결점: 현재 사용자 증상 해결에 불필요한 데이터 변동과 다운타임을 만든다.

이번 작업에서는 B만 수행한다. C는 별도 인벤토리·평가 기준·롤백 계획을 승인받은 뒤 진행한다.

## 4. 권위 판정 계약

권위 문구는 온톨로지의 정적 결론이 아니라 최종 선택된 `direct_chunks`의 메타데이터에서 계산한다.

### 4.1 출처 분류

- `own`: `is_own_company is True`
- `standard`: `product_type == "표준약관"` 또는 `doc_short == "표준약관"`
- `other`: 위 두 조건에 해당하지 않는 문서

현재 표준약관 청크는 `is_own_company`가 `None`일 수 있으므로, 즉시 패치에서는 `product_type`/`doc_short` 보조 판정을 반드시 유지한다. 다음 인제스트부터는 설정에서 `is_own_company=False`가 명시된다.

### 4.2 표시 문구

| 선택 출처 | 문구 |
|---|---|
| 자사만 | `현재 선택한 {세대} 자사 상품약관의 직접 조항 근거입니다.` |
| 표준만 | `{세대} 표준약관은 등록되어 있으며, 현재 답변은 해당 표준약관의 직접 조항을 근거로 합니다.` |
| 자사+표준 | `현재 선택한 {세대} 자사 상품약관과 표준약관의 직접 조항을 함께 근거로 확인했습니다.` |
| 기타/불명 | `현재 선택한 {세대} 기준 문서의 직접 조항 근거입니다.` |

출처가 혼합되면 자사 우선 한 줄로 축약하지 않는다. `등록된 자사 상품약관이 없다`는 주장은 실제 문서 인벤토리 조회 없이 생성하지 않는다.

### 4.3 낡은 프로필 값 차단

`_authority_note()`는 더 이상 `profile["standard_reference_note"]`를 읽지 않는다. 기본 온톨로지의 값도 중립화하거나 제거하되, 활성 온톨로지에 과거 값이 남아 있어도 런타임 답변에 유출되지 않아야 한다. 활성 매니페스트를 승인 절차 없이 직접 덮어쓰지 않는다.

## 5. 설정 및 인제스트 계약

`PdfSource`에 다음 필드를 복구한다.

```python
policy_generation: str | None = None
```

문서 설정은 다음과 같이 명시한다.

- 신한 이지로운 실손의료보험 자사약관: `policy_generation="4th"`
- 표준약관: `policy_generation="5th"`, `is_own_company=False`

`src/parser/chunker.py`는 이미 `policy_generation`을 확장 메타데이터 필드로 전달하므로 생산 코드 변경보다 회귀 테스트가 우선이다. `False`를 누락값으로 취급하지 않고 청크에 그대로 보존하는지도 검증한다.

## 6. 사용자 영향과 예상 결점

### 6.1 긍정적 영향

- 5세대 표준약관이 등록되어 있다는 사실과 실제 답변 근거가 명확해진다.
- 표준약관과 자사 상품약관을 혼동하는 표현이 줄어든다.
- 다음 전체 인제스트에서도 4·5세대 필터가 유지된다.
- 향후 자사 5세대 약관 추가 시 정적 문구를 다시 수정하지 않아도 된다.

### 6.2 발생 가능한 결점과 완화책

1. **문구 스냅샷/회귀 테스트 실패**
   기존 문자열을 고정한 테스트와 화면 검증이 실패할 수 있다. 권위별 계약 테스트로 교체하고, 내용이 아닌 잘못된 부재 단정의 미노출도 검사한다.

2. **혼합 출처의 과도한 권위 주장**
   `any(own)` 방식은 표준 청크가 섞여도 자사만 사용한 것처럼 보인다. 집합 기반으로 `own`, `standard`, `other`를 별도 판정한다.

3. **현재 인덱스의 `is_own_company=None`**
   설정에 `False`를 추가해도 재인덱스 전 기존 청크는 바뀌지 않는다. 즉시 런타임은 `doc_short`/`product_type` 보조 판정을 사용한다.

4. **활성 온톨로지의 낡은 문구 잔존**
   승인되지 않은 활성 파일 직접 수정은 거버넌스를 깨뜨릴 수 있다. 런타임에서 프로필 문구 사용을 제거하고, 기본 매니페스트만 중립화한다.

5. **과거 대화와 새 대화의 표현 차이**
   저장된 과거 답변은 그대로 남으므로 동일 스레드에서 구문이 다를 수 있다. 이는 감사 가능성을 보존하기 위한 의도된 결과이며, 과거 메시지를 일괄 수정하지 않는다.

6. **표준약관 전체의 과도한 5세대 태깅**
   이번 패치는 탈모 직접 조항의 정확성을 보존하지만 문서 전체 구간 분류는 고치지 않는다. 별도 데이터 마이그레이션 과제로 추적한다.

7. **`PdfSource` 생성자 호환성**
   필드 복구가 위치 인자 생성자에 영향을 줄 수 있다. 모든 `PdfSource(` 사용을 검색하고 새 필드는 기본값을 가진 뒤쪽 필드로 추가하며 설정은 키워드 인자를 사용한다.

8. **운영 인덱스 불필요 변동**
   단순 설정 복구를 이유로 즉시 재인덱스하면 검색 순위가 달라질 수 있다. 이번 배포에서는 인제스트, GraphDB 재구축, 운영 DB 재작성 모두 금지한다.

## 7. 검증 기준

- 표준만 선택한 5세대 답변에 `5세대 표준약관은 등록되어 있으며`가 포함된다.
- 같은 답변에 `등록된 5세대 자사 상품 약관이 없`이 포함되지 않는다.
- 자사만, 자사+표준, 불명 출처가 각각 계약 문구를 반환한다.
- 프로필에 낡은 `standard_reference_note`를 주입해도 최종 답변에 나타나지 않는다.
- 설정의 자사 실손은 4세대, 표준약관은 5세대·비자사로 선언된다.
- 청크 생성 시 `policy_generation`과 `is_own_company=False`가 보존된다.
- 세대 필터와 탈모 직접 청크 고정은 기존과 동일하게 동작한다.
- 기존 저장 대화는 수정되지 않는다.
- 현재 운영 인덱스와 GraphDB는 재구축되지 않는다.

## 8. 제외 범위와 후속 과제

이번 변경에서 제외한다.

- 표준약관 856개 청크의 섹션별 세대 재분류
- BM25/Chroma/GraphDB 전체 재구축
- 기존 채팅 답변 재생성 또는 DB 마이그레이션
- 신규 보험 판단 룰 또는 후보 룰의 승인
- 5세대 자사 상품약관이 실제로 존재하는지에 대한 정적 단정

후속으로 표준약관 복합 문서의 섹션 인벤토리, 구간별 세대 라벨, 검색 평가 세트, 인덱스 전환·롤백 절차를 별도 명세로 작성한다.

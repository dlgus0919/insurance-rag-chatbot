## 문제 1 — 충수절제술 코드 조회 시 "관련 내용 없음" 오답

### 증상
- 질문: "충수절제술 코드를 알려줘"
- 실제 답변: "해당 문서에서 관련 내용을 찾을 수 없습니다."
- 실제 정답: Q2861(단순), Q2862(천공성), Q2863(충수농양절제 및 충수주위 농양배액술)

### 근본 원인

심평원 PDF에서 충수절제술 항목은 **상위 분류명(자-286)과 하위 코드(Q2861~Q2863)가 서로 다른 행에 분리**되어 있다.

```
자-286  [코드 없음]  충수절제술 Appendectomy       ← 이 행에는 코드가 없음
         Q2861       가. 단순 Simple
         Q2862       나. 천공성 Perforated
         Q2863       다. 충수농양절제 및 ...
```

PDF 파싱 시 텍스트를 500~600자 단위로 청킹하면, "충수절제술"이라는 단어가 있는 청크와 "Q2861"이 있는 청크가 **서로 다른 청크로 분리**될 수 있다. 결과적으로 벡터 검색이 "충수절제술"이 포함된 청크를 찾아도 코드가 없는 청크를 가져오거나, 코드가 있는 청크를 가져와도 수술명이 빠져 있어 LLM이 연결하지 못한다.

### 해결 방법

**`src/ingest/chunker.py` — `chunk_overlap_tokens` 값 증가**

현재 `chunk_overlap_tokens = 80`으로 설정되어 있다. 이 값을 **200 이상**으로 늘려야 분리된 행이 다음 청크에 중복 포함되어 수술명과 코드의 연결성이 유지된다.

`.env` 파일에서 수정:
```
CHUNK_OVERLAP_TOKENS=200
```

**`src/retrieval/prompts.py` — SYSTEM_PROMPT에 아래 지침 추가**

```
- 수술명만 알고 코드가 없는 경우, 같은 수술의 세부 분류(가/나/다 또는 유형별)가 별도 코드로 존재할 수 있음을 안내하라.
- 단일 코드가 아닌 복수 코드(가/나/다)가 존재하는 경우 모두 나열하라.
```

**수정 후 재인덱싱 필수**

overlap 값을 변경하면 청킹 결과가 달라지므로 반드시 재인덱싱이 필요하다:
```bash
python scripts/01_ingest.py --pdf data/raw/BZ202603053039374.pdf --rebuild --embedding-model BAAI/bge-m3
python scripts/01_ingest.py --pdf "data/raw/2.약관_신한 이지로운 실손의료보험(무배당)_20260401_0325.pdf" --embedding-model BAAI/bge-m3
```

## 문제 2 — "해당 문서에서 찾을 수 없습니다" + 올바른 답변이 동시에 출력되는 모순

### 증상
- 질문: "식도조루술의 수술코드와 수술 해설을 알려줘"
- 실제 답변 구조:
  - 1번째 줄: "해당 문서에서 관련 내용을 찾을 수 없습니다."
  - 이어서: "식도조루술의 코드는 Q2333 이며 ... (심평원 PDF 956p)"
  - 이어서: "따라서, 식도조루술의 코드는 Q2333 입니다."

### 근본 원인

`src/retrieval/prompts.py`의 `SYSTEM_PROMPT`에 **"검색 결과가 없을 때 '해당 문서에서 관련 내용을 찾을 수 없습니다'라고 답하라"는 지침**이 있는데, Qwen2.5:7b 모델이 이를 잘못 해석하여 검색 결과가 충분히 있음에도 답변 첫 줄에 해당 문구를 습관적으로 출력하고 있다.

또한 `build_user_prompt()` 함수가 LLM에게 "검색된 청크가 몇 개 있다"는 사실을 명시적으로 알려주지 않아, LLM이 스스로 결과 유무를 판단하다가 오류를 범하고 있다.

### 해결 방법

**`src/retrieval/prompts.py` — SYSTEM_PROMPT 수정**

기존 문구를 찾아서 아래처럼 조건을 명확하게 교체:

```
[중요 규칙]
- 아래 [검색된 문서 내용]에 관련 내용이 조금이라도 있으면, 반드시 그 내용을 바탕으로 답변하라.
- "해당 문서에서 관련 내용을 찾을 수 없습니다"는 [검색된 문서 내용]이 완전히 비어 있을 때만 출력하라.
- 절대로 답변 첫 줄에 "찾을 수 없습니다"를 출력한 뒤 이어서 관련 내용을 설명하는 모순된 답변을 하지 마라.
```

**`src/retrieval/prompts.py` — `build_user_prompt()` 함수 수정**

검색된 청크 수를 LLM에게 명시적으로 전달:

```python
def build_user_prompt(question: str, chunks: list[dict]) -> str:
    context = build_context(chunks)
    chunk_count = len(chunks)
    return f"""아래는 질문과 관련하여 문서에서 검색된 내용입니다. 총 {chunk_count}개의 관련 청크가 검색되었습니다.
반드시 아래 내용을 바탕으로 답변하세요.

[검색된 문서 내용]
{context}

[질문]
{question}
"""
```

## 문제 3 — 임신·출산 질문에 "보상 불가" 대신 모호한 답변 출력

### 증상
- 질문: "임신·출산 관련 비용도 실손보험에서 보상받을 수 있나요?"
- 실제 답변: "임신·출산 관련 비용은 회사가 보상하는 상해 또는 질병으로 인한 경우에만 실손보험에서 보상받을 수 있습니다."
- 올바른 답변: "원칙적으로 보상하지 않습니다. 단, 상해로 인한 경우 예외."

### 근본 원인

약관 PDF 원문의 구조:
> "피보험자가 임신, 출산(제왕절개 포함), 산후기로 입원 또는 통원한 경우 → **보상 안 함**. **다만**, 회사가 보상하는 상해로 인하여 입원·통원한 경우에는 보상함."

원문은 **"원칙(보상 불가) + 단서(예외)"** 구조다. 그런데 LLM이 "다만" 이후의 단서 조항을 **원칙인 것처럼 뒤집어** 해석하여 "상해·질병으로 인한 경우에만 보상받을 수 있다"는 반대 의미의 답변을 생성하고 있다.

이는 RAG 검색 자체의 문제가 아니라 **LLM의 법률·약관 문서 해석 지침 부재** 때문이다.

### 해결 방법

**`src/retrieval/prompts.py` — SYSTEM_PROMPT에 약관 해석 규칙 추가**

```
[약관 문서 해석 규칙]
- 약관에서 "보상하지 않는다"는 표현이 나오면 반드시 "보상 불가"를 첫 문장에 명시하라.
- "다만", "단", "단서"로 시작하는 예외 조항이 있으면, 원칙(보상 불가)을 먼저 설명하고 그 다음에 예외를 설명하라.
- 절대로 예외 조항을 원칙인 것처럼 뒤집어서 답변하지 마라.

올바른 답변 예시:
  "임신·출산 관련 의료비는 원칙적으로 보상하지 않습니다.(약관 PDF 35p)
   단, 회사가 보상하는 상해로 인하여 입원·통원한 경우에는 예외적으로 보상합니다."

잘못된 답변 예시 (절대 금지):
  "상해 또는 질병으로 인한 경우에만 보상받을 수 있습니다."
```

## 문제 4 — 정신질환 질문에 완전히 엉뚱한 답변 출력

### 증상
- 질문: "정신질환 치료비는 실손보험에서 보상받을 수 있나요?"
- 실제 답변: 이전 대화(식도조루술, 임신·출산)와 관련된 내용을 언급하며 전혀 엉뚱한 답변

### 근본 원인 (2가지가 복합적으로 작용)

**원인 A — 멀티턴 대화 히스토리가 검색 쿼리를 오염시킴 (핵심 원인)**

`src/chat/engine.py`의 `rewrite_question()` 함수:

```python
def rewrite_question(question: str, history: list[dict]) -> str:
    if not history:
        return question
    recent = " ".join(item.get("content", "") for item in history[-4:] if item.get("role") == "user")
    return f"{recent}\n현재 질문: {question}" if recent else question
```

이 함수가 이전 사용자 질문 4개를 현재 질문에 그대로 이어붙여 검색 쿼리로 사용한다.
즉 실제 검색 쿼리가 다음처럼 만들어진다:

```
"충수절제술 코드를 알려줘 식도조루술의 수술코드와 수술 해설을 알려줘 임신·출산 관련 비용도 실손보험에서 보상받을 수 있나요?
현재 질문: 정신질환 치료비는 실손보험에서 보상받을 수 있나요?"
```

이 긴 쿼리의 벡터 임베딩은 "정신질환" 방향이 아니라 "식도조루술", "충수절제술" 방향으로 편향되어 엉뚱한 청크를 검색해온다.

**원인 B — 약관 PDF 청크의 `doc_title` 미설정**

출처 패널에서 모든 출처가 "[심평원 PDF]"로만 표시되고 있다. 약관 PDF 청크의 `doc_title`이 심평원 PDF와 동일하게 설정되어 있어 정신질환 관련 약관 조항 청크가 검색 결과에서 심평원 청크에 밀리고 있다.

### 해결 방법

**① `src/chat/engine.py` — `rewrite_question()` 함수 수정 (최우선)**

이전 질문을 검색 쿼리에서 완전히 제거:

```python
def rewrite_question(question: str, history: list[dict]) -> str:
    # 이전 질문을 검색 쿼리에 포함하지 않는다.
    # 히스토리를 이어붙이면 벡터 검색이 오염되어 엉뚱한 청크가 검색된다.
    return question
```

**② `src/ingest/pdf_parser.py` — PDF 파일명 기반으로 `doc_title` 자동 설정**

`src/config.py`의 `doc_title` 기본값이 "건강보험 행위 급여·비급여 목록표..."로 하드코딩되어 있어 약관 PDF 청크에도 동일하게 적용되고 있다. `pdf_parser.py`에서 파일명을 읽어 자동으로 구분하도록 수정:

```python
def get_doc_title(pdf_path: str) -> str:
    if "약관" in pdf_path:
        return "신한 이지로운 실손의료보험 약관"
    return "심평원 행위 급여·비급여 목록"
```

각 페이지 딕셔너리에 `doc_title`을 이 함수의 반환값으로 설정해야 한다.

## 문제 5 — MRI 질문에 "관련 내용 없음" 오답

### 증상
- 질문: "MRI 검사 비용은 실손보험에서 보상되나요?"
- 실제 답변: "해당 문서에서 관련 내용을 찾을 수 없습니다."
- 실제 정답: 약관 PDF 69p에 MRI(자기공명영상진단)가 3대비급여 항목으로 명시

### 근본 원인 (2가지 복합)

**원인 A — 동의어 처리 부재**

약관 PDF에서 MRI는 "자기공명영상진단"으로만 표기되어 있다. 사용자가 "MRI"로 질문하면 임베딩 유사도가 낮게 계산되어 관련 청크가 TOP_K 안에 포함되지 않는다.

**원인 B — 문제 4의 `doc_title` 미설정 문제 동일하게 적용**

약관 PDF 청크가 검색 결과에서 누락되고 심평원 PDF 청크만 반환되어 "관련 내용 없음"으로 보인다.

### 해결 방법

**① `src/retrieval/retriever.py` — 쿼리 확장(Query Expansion) 기능 추가**

```python
MEDICAL_SYNONYMS = {
    "MRI": ["자기공명영상진단", "자기공명영상", "MRI"],
    "CT": ["전산화단층촬영", "CT"],
    "맹장": ["충수", "충수절제술"],
    "맹장수술": ["충수절제술", "Appendectomy"],
    "도수치료": ["도수치료", "근골격계 기능 개선"],
    "주사": ["주사료", "주사치료"],
}

def expand_query(query: str) -> str:
    """의료 동의어를 추가하여 검색 쿼리를 확장한다."""
    extra_terms = []
    for keyword, synonyms in MEDICAL_SYNONYMS.items():
        if keyword in query:
            extra_terms.extend(synonyms)
    if extra_terms:
        return query + " " + " ".join(set(extra_terms))
    return query
```

`retrieve()` 함수 내에서 검색 직전에 호출:
```python
def retrieve(self, query: str, top_k: int) -> list[dict]:
    expanded_query = expand_query(query)
    # expanded_query를 임베딩하여 ChromaDB 검색
    ...
```

**② `src/retrieval/prompts.py` — 동의어 인식 지침 추가**

```
[의료 용어 동의어 인식]
- MRI = 자기공명영상진단 = 자기공명영상
- CT = 전산화단층촬영
- 맹장수술 = 충수절제술
- 도수치료 = 근골격계 기능 개선 치료
검색된 문서에 위 동의어 중 하나가 포함되어 있으면, 해당 질문과 관련된 내용으로 간주하고 답변에 활용하라.
```

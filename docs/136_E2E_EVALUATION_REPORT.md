## 3. 결점 심층 분석 및 해결 방안

### 가. 보상액 산출 오류 분석 (Standard Matcher 엑셀 맵핑 결함)

모든 모델이 "도수치료", "MRI", "표적항암제"와 같은 비급여 청구 테스트에서 100% Fail(오답) 처리되었습니다. (예: 도수치료 10만원 청구 시 예상 공제액 3만원(4세대) 또는 5만원(5세대)이 아닌 **10만원 전액 공제(지급액 0원) 산출**)

*   **오류 원인 파악 (로그 분석)**:
    계산 파이프라인 로그를 뜯어본 결과, `Standard Matcher` 모듈이 "도수치료"라는 입력값을 검색할 때 비급여표준모델 엑셀 데이터 중 **보상의견이 '면책'인 특수 코드(예: 51040, 분류: '공상')를 가장 우선적으로 매핑해 버리는 치명적 결함**이 발견되었습니다.
    파이프라인(`pipeline.py`의 `_is_exclusion_match`)은 하나라도 면책 코드가 매핑되면 해당 청구를 즉시 전액 공제(지급액 0원)로 덮어쓰도록 하드코딩되어 있습니다.
*   **해결 방안 (조항 및 로직 개선)**:
    1.  **동음이의어/다중 코드 처리**: 비급여 항목명 조회 시 여러 코드가 검색되면 무조건 '면책'을 선택할 것이 아니라, 사용자에게 **정확한 코드 선택을 요구(Disambiguation)** 하거나 기본적으로 **가장 일반적인 '보상' 코드를 우선**하도록 `standard_matcher.py`의 우선순위 로직을 수정해야 합니다.
    2.  **공상/산재 필터링**: 일반 실손 청구 컨텍스트에서는 '공상', '산재' 등 특수 목적 코드는 매칭 가중치를 대폭 낮춰야 합니다.

### 나. 일반/정형 검색 오류 분석 (GraphDB 및 채점 한계)

모든 모델에서 일반 텍스트 질의(예: "4세대 도수치료 한도는?")가 "Missing keywords" 사유로 Fail 되었습니다.

*   **오류 원인 파악**:
    1.  **엄격한 Hard-matching 채점 로직**: 테스트 스크립트는 `"350만원"`, `"50회"`, `"보상하지 않습니다"`와 같은 정확한 키워드 완전 일치를 요구합니다. 하지만 LLM은 "350만 원"(띄어쓰기), "보상하지 아니합니다", "오십 회" 등으로 유연하게 대답하기 때문에 정답을 맞추고도 오답 처리되었습니다.
    2.  **GraphDB 크로스 레퍼런스 부족**: "백내장 수술 다초점 렌즈"와 같은 복합 질의의 경우, GraphDB에서 '백내장' 노드와 '다초점 렌즈' 엣지 간의 직접적인 인과(면책 사유) 연결이 약해, 검색기가 단편적인 청구 서류만 가져오고 약관 원문을 놓치는 현상이 발견되었습니다.
*   **해결 방안**:
    1.  **평가 로직 고도화**: 키워드 일치 대신 **LLM-as-a-Judge(평가용 LLM 모델)** 를 도입하여 의미적 일치(Semantic Similarity) 여부로 채점을 수행해야 합니다.
    2.  **그래프 지식 구축 강화**: 특정 질병과 치료 재료(예: 백내장-다초점렌즈, 도수치료-체외충격파) 간의 명시적인 약관 면책 엣지(Edge)를 추가로 생성하도록 `scripts/build_graph.py` 인덱싱 룰을 강화해야 합니다.

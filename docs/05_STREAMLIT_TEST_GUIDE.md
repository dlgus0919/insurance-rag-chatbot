# Streamlit UI 테스트 가이드

이 문서는 보험사 실무 담당자가 Streamlit UI(웹 화면)를 처음 열고 기능을 확인하기 위한 단계별 안내입니다. 개발 지식이 없어도 화면에 보이는 요소와 답변 내용을 기준으로 정상 동작 여부를 확인할 수 있습니다.

## 1. 실행 전 준비

1. Ollama 앱이 실행 중인지 확인합니다.
   - macOS 오른쪽 위 메뉴바에 Ollama 아이콘이 보이면 정상입니다.
   - 터미널에서 아래 명령을 실행했을 때 `gemma3:4b`가 목록에 보이면 정상입니다.

```bash
ollama list
```

2. 프로젝트의 `.env` 파일에서 사용 모델을 확인합니다.
   - 아래 줄이 보이면 정상입니다.

```bash
OLLAMA_MODEL=gemma3:4b
```

3. 터미널에서 프로젝트 폴더로 이동합니다.

```bash
cd "/Users/june_kim/Documents/Claude/Projects/보험 문서 RAG 챗봇"
```

4. Streamlit UI를 실행합니다.

```bash
streamlit run src/ui/streamlit_app.py
```

5. 브라우저에서 아래 주소를 엽니다.
   - Streamlit이 자동으로 브라우저를 열 수도 있습니다.

```text
http://localhost:8501
```

6. 첫 질문을 입력할 때는 모델 로딩 시간이 걸릴 수 있습니다.
   - 최초 1회 30초 내외로 기다린 뒤 답변이 나오면 정상입니다.

## 2. UI 구성 확인

왼쪽 사이드바에서 모델명이 보이면 정상입니다.

왼쪽 사이드바에서 Top-K 슬라이더가 4~12 범위로 보이면 정상입니다. Top-K는 검색할 원문 후보 개수입니다.

왼쪽 사이드바에서 온도 슬라이더가 0.0~0.7 범위로 보이면 정상입니다. 온도는 답변 표현의 다양성을 조절하는 값입니다.

왼쪽 사이드바에서 `대화 초기화` 버튼이 보이면 정상입니다.

중앙 채팅창 아래쪽에 질문 입력란이 보이면 정상입니다.

질문 후 사용자 질문과 챗봇 답변이 차례대로 쌓이면 메시지 히스토리(대화 기록)가 정상입니다.

답변 아래에 `출처 보기` 접힘 영역(expander, 클릭하면 펼쳐지는 영역)이 보이면 정상입니다.

## 3. 단계별 테스트 시나리오 5개

아래 질문을 순서대로 입력하고, 각 확인 포인트를 체크합니다.

### 시나리오 1 — 심평원 코드 조회 (단일 문서)

질문:

```text
AA157은 어떤 기관의 초진 진찰료이며 점수는 얼마인가요?
```

확인 포인트:

- 답변에 `상급종합병원`이 보이면 정상입니다.
- 답변에 구체적인 점수 수치가 보이면 정상입니다.
- 답변 마지막에 `[출처: 심평원, ..., p.101]` 또는 이와 유사한 출처 표기가 보이면 정상입니다.
- `출처 보기`를 클릭했을 때 심평원 원문이 보이면 정상입니다.

### 시나리오 2 — 약관 진단코드 보상 여부 (단일 문서)

질문:

```text
N39.3 진단이 실손의료비 약관에서 보상가능한지 알려줘.
```

확인 포인트:

- 답변에 `요실금` 또는 `N39.3`이 보이면 정상입니다.
- 답변에 `보상하지 않습니다` 또는 비슷한 의미의 표현이 보이면 정상입니다.
- 출처가 `심평원`이 아니라 `약관`으로 표시되면 정상입니다.
- 답변에 질병급여, 질병비급여, 3대비급여 중 하나 이상이 보이면 정상입니다.

### 시나리오 3 — 심평원 수술코드 조회

질문:

```text
식도조루술의 코드를 알려줘.
```

확인 포인트:

- 답변에 코드 `Q2333`이 보이면 정상입니다.
- 출처가 `심평원`으로 표시되면 정상입니다.
- `출처 보기`를 클릭했을 때 식도 관련 원문이 보이면 정상입니다.

### 시나리오 4 — 약관 의미 검색

질문:

```text
실손의료보험 약관에서 3대비급여에 해당하는 항목은 무엇인가요?
```

확인 포인트:

- 답변에 도수치료, 비급여 주사료, MRI/MRA 중 하나 이상이 보이면 정상입니다.
- 출처가 `약관`으로 표시되면 정상입니다.

### 시나리오 5 — 멀티턴 연속 질문 (히스토리 누적 확인)

이전 대화가 화면에 남아 있는 상태에서 아래 질문을 추가로 입력합니다.

질문:

```text
그렇다면 3대비급여 중 도수치료의 보상 한도는 어떻게 되나요?
```

확인 포인트:

- 이전 질문과 답변이 화면에 그대로 남아 있으면 정상입니다.
- 새 질문 아래에 새 답변이 추가되면 정상입니다.
- 왼쪽 사이드바의 `대화 초기화` 버튼을 클릭했을 때 대화 기록이 지워지면 정상입니다.

## 4. 출처 expander 사용법

각 답변 하단의 `출처 보기`를 클릭하면 답변에 사용된 원문 청크(검색된 문서 조각)가 펼쳐집니다.

펼쳐진 원문에서 문서명이 `심평원` 또는 `약관`으로 표시되는지 확인합니다. 문서명이 보이면 정상입니다.

펼쳐진 원문에서 조문이나 절 이름, 페이지 번호가 함께 보이는지 확인합니다. 예를 들어 `제4조(보상하지 않는 사항)` 또는 `제1절 진찰료`, `p.101` 같은 표시가 보이면 정상입니다.

시나리오 1의 출처는 `심평원`, 시나리오 2의 출처는 `약관`으로 다르게 표시되는지 비교합니다. 질문 성격에 맞게 문서명이 다르게 보이면 정상입니다.

## 5. 이상 증상 대처

| 상황 | 원인 | 해결 방법 |
|---|---|---|
| `Ollama 서버에 연결할 수 없습니다` 메시지가 보임 | Ollama 앱이 꺼져 있습니다. | Ollama 앱을 실행하거나 터미널에서 `ollama serve`를 실행하면 정상입니다. |
| 응답이 없거나 너무 느림 | 검색 후보가 많거나 모델 응답이 늦을 수 있습니다. | 왼쪽 사이드바에서 Top-K를 4로 줄이고 온도를 0.1로 낮춘 뒤 다시 질문하면 정상입니다. |
| `제공된 문서에서 확인되지 않습니다`라는 답변이 나옴 | 질문이 너무 넓거나 문서의 표현과 다를 수 있습니다. | 코드번호나 조문명처럼 구체적인 단어를 포함해 다시 질문하면 정상입니다. |
| 인덱스 오류가 보임 | 검색 인덱스(문서를 검색하기 위한 저장 데이터)가 없거나 오래됐을 수 있습니다. | 터미널에서 아래 명령을 다시 실행하면 정상입니다. |
| 8501 포트가 이미 사용 중이라고 나옴 | 다른 Streamlit 화면이 이미 실행 중입니다. | 다른 포트로 실행하면 정상입니다. |

인덱스 오류 해결 명령:

```bash
python scripts/ingest.py --stage index
```

포트 충돌 해결 명령:

```bash
streamlit run src/ui/streamlit_app.py --server.port 8502
```

## 6. 테스트 완료 체크리스트

아래 항목을 모두 확인했으면 테스트 완료입니다.

□ 심평원 질문에 심평원 출처가 표시된다

□ 약관 질문에 약관 출처가 표시된다

□ 출처 expander에서 원문이 보인다

□ 연속 질문 시 히스토리가 누적된다

□ 대화 초기화 버튼이 작동한다

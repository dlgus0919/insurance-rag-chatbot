- 현재 로컬 Mac에서는 Ollama, vLLM, SGLang 서버가 실행 중이 아니어서 실제 LLM 최종 답변 생성은 수행하지 못했습니다.
- 따라서 아래의 “답변 미리보기”는 모델이 생성한 자연어 답변이 아니라, 각 버전의 RAG가 LLM에 전달할 상위 검색 근거를 추출형으로 요약한 것입니다.
- 이 비교는 “검색 최적화 적용 후 LLM에 들어가는 근거가 어떻게 달라지는지”를 확인하기 위한 것입니다.

## 관찰 결과 요약

| 관찰 항목 | 내용 |
| --- | --- |
| 코드/조항 질의 | 수정 후에는 `exact_code_lookup`, `clause_or_appendix_lookup`으로 분류되어 BM25 비중이 커졌습니다. 코드 질의는 dense 검색을 생략해 리소스 절약 효과가 있습니다. |
| 모호한 보상 질의 | `도수치료`, `엠알아이` 같은 표현은 Chroma 비중이 높아져 문장 의미 기반 근거를 더 넓게 탐색합니다. |
| 문서별 비교 | `cross_doc_compare`는 BM25와 Chroma를 0.5/0.5로 균형 있게 사용하도록 분기됩니다. |
| 실제 답변 비교 한계 | 로컬에 LLM 서버가 없어 최종 자연어 답변 대신 LLM 입력 근거 미리보기를 비교했습니다. DGX에서 모델을 띄우면 같은 질문 세트로 최종 답변 비교가 가능합니다. |
| 성능 수치 해석 | 이번 실행 시간은 임베딩 모델 로딩과 로컬 캐시 상태 영향을 받으므로 엄밀한 성능 벤치마크로 보기는 어렵습니다. 다만 코드 질의에서 dense 검색 생략 로직은 리소스 절약 방향으로 동작합니다. |

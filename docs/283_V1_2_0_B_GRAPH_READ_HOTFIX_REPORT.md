# v1.2.0.b GraphDB 읽기 보조 파일 핫픽스

## 원인

실사용 일반 질의의 GraphDB 조회가 SQLite `mode=ro` 연결을 사용하면서 런타임 GraphDB에 `-wal`/`-shm` 보조 파일을 남겼다. 이후 안전 기준 온톨로지 로더가 보조 파일을 체크포인트되지 않은 GraphDB로 판정해 다음 질의의 온톨로지 무결성 조회가 실패했고, 브라우저에는 전송 실패로 표시될 수 있었다.

## 최소 변경

`GraphRetriever`의 읽기 연결을 SQLite `immutable=1` 읽기 전용으로 변경했다. 계산 규칙, GraphDB 내용, 온톨로지 개념, 원문 자료는 변경하지 않았다.

## 운영 정리

앱 재기동 후 WAL 체크포인트 결과가 `0|0|0`임을 확인하고, 0바이트 WAL 및 남은 SHM 보조 파일을 정리했다. 안전 기준 온톨로지 로드 후에도 보조 파일이 다시 생성되지 않는 것을 확인했다.

## 검증

- 읽기 조회 후 SQLite 보조 파일이 생성되지 않는 회귀 테스트를 추가했다.
- 해당 회귀 테스트 및 기존 GraphRetriever 핵심 테스트를 실행했다.
- 전체 GraphRetriever 테스트는 온톨로지 미로딩에 의존하는 기존 fallback 테스트 1건이 별도로 실패했다.
- 운영 앱 헬스체크와 안전 기준 온톨로지 무결성 로드는 정상이다.

# NVIDIA DGX Spark 로컬 서버용 LLM 후보 조사 보고서

> **작성:** 기획자
> **작성일:** 2026-05-07
> **목적:** RAG 챗봇 앱을 NVIDIA DGX Spark에서 로컬 서버로 구동할 때, 답변 생성용 LLM을 *우리 사용 사례에 가장 적합한 고성능 모델*로 교체하기 위한 후보 비교 자료
> **현재 사용 모델:** `exaone3.5:7.8b` (로컬), `gpt-5.x 계열` (Cloud)

---

## 1. DGX Spark 하드웨어 요약 (모델 선택의 제약 조건)

| 항목 | 사양 (공개 자료 기준) |
|---|---|
| 칩셋 | NVIDIA GB10 Grace Blackwell Superchip (ARM CPU + Blackwell GPU) |
| 통합 메모리 | **128GB LPDDR5x** (CPU·GPU 공유) |
| 메모리 대역폭 | 약 273 GB/s |
| AI 성능 | FP4 기준 약 1 PFLOPs |
| 권장 양자화 | **FP4 / FP8 (NVFP4·FP8 텐서코어 지원)** |
| 서빙 스택 | vLLM, TensorRT-LLM, Ollama, llama.cpp 모두 호환 |
| 모델 한도 (단일 노드) | FP4 기준 약 200B, FP8 기준 약 70B, FP16 기준 약 32~40B |

**핵심 시사점:**
- 단일 사용자·소규모 동시 사용자 챗봇 용도라면 **32B~70B 클래스**가 sweet spot
- 메모리 대역폭이 토큰 처리 속도의 병목 → 32B FP8(~32GB)에서 약 8~12 tok/s, 70B FP4(~35GB)에서 약 7~9 tok/s 수준 기대
- 우리 RAG 챗봇 UX(스트리밍 답변, 한 번 호출당 800~1500 토큰 생성)에는 충분

## 2. 우리 사용 사례 요구사항

| 요구 | 우선순위 | 함의 |
|---|---|---|
| **한국어 정확도** | 최상 | 자사·타사 약관, 심평원 고시, 사례집 모두 한국어. 한국어 RAG SOTA가 절대적 |
| **인용·구조화 출력 준수** | 최상 | `[출처: …]`, 약관 정형 폼의 형식별 라벨 (코드/분류/점수/보상) 준수 |
| **컨텍스트 충실 (anti-hallucination)** | 최상 | 보험 보상 판정의 신뢰성 → 컨텍스트 외 단정 금지 |
| **긴 컨텍스트 (≥ 32K)** | 상 | top-K=8 약관 청크 + 표 JSON 직렬화 → 6~10K 토큰. 비교 모드는 더 큼 |
| **표·코드 추출 능력** | 상 | 약관·심평원 표, 표준코드(`std_cd`) 매칭 |
| **명령 추종(Instruction)** | 상 | 퀵 코드 폼·약관 정형 폼의 시나리오별 시스템 프롬프트 준수 |
| **추론 능력(option)** | 중 | 면·부책 조건부 판정에 다중 hop 사고 도움. 단, **RAG에서는 과한 reasoning이 컨텍스트 무시 부작용** — 끄거나 약하게 설정 가능해야 |
| **라이선스(상업·사내 사용)** | 중 | 신한EZ 사내 운용. 상업 라이선스 또는 사내 사용 명시적 허용 필요 |
| **서빙 도구 호환** | 중 | vLLM·TensorRT-LLM·Ollama·llama.cpp 모두 지원이면 유리 |
| **멀티모달(option)** | 하 | 과제 2 영수증·진단서 이미지 처리 확장 시 가산점 |

## 4. 후보별 상세 (왜 우리 사용 사례에 맞는가)

### 4.1 ① EXAONE-3.5-32B-Instruct — 최우선 추천

- **개발사:** LG AI Research, 2024-12 공개
- **강점:**
  - 한국어 ↔ 영어 이중 언어로 학습된 한국어 SOTA. 약관·법률·고시 텍스트와 같은 격식체 한국어에서 특히 강함
  - 32B 클래스 → DGX Spark의 128GB 메모리에 FP8로 **여유 있게 적재**되며 추론 속도도 충분
  - 32K 컨텍스트 → 우리 top-K=8 청크 + 메타 + 표 직렬화에 충분
  - 인용·구조화 출력 준수도가 7.8B 대비 크게 향상됨이 자체 벤치(KMMLU·Ko-IFEval·KoBEST)에서 검증
- **약점:**
  - 컨텍스트 128K는 아니므로 *약관 비교 모드*에서 너무 많은 약관을 한 번에 넣을 수는 없음 (chunk 수 제한)
  - reasoning 전용 변형(EXAONE Deep 시리즈)은 별도. 일반 instruct가 RAG에 더 맞음
- **우리 시스템 적합도:** 알파에서 7.8B로 이미 운용 중 → 32B로 확장은 *호환성 가장 높은 업그레이드 경로*. 시스템 프롬프트 재사용성 100%.
- **권장 양자화:** FP8 (32GB 사용, 약 10~12 tok/s)

### 4.2 ② Qwen2.5-72B-Instruct — 최고 성능 후보

- **개발사:** Alibaba Qwen Team, 2024-09 공개
- **강점:**
  - 다국어 SOTA. KMMLU·HAE-RAE·LogicKor 등 한국어 벤치마크에서도 7B/14B 대비 압도적
  - **128K 컨텍스트** → 약관 비교 모드, GraphRAG 결합 시 다중 hop 컨텍스트를 한 번에 처리
  - 명령 추종(IFEval)에서 GPT-4o 클래스 근접
  - 표·코드 추출·JSON 출력 등 구조화 능력 매우 강함
- **약점:**
  - 72B → FP8에서 ~72GB → DGX Spark에 적재는 가능하나 *동시 처리 청크 수에 따라 KV 캐시 압박*
  - 라이선스: Tongyi Qianwen 라이선스, 사용자 수 임계 이하라면 상업 사용 무료 (사내 캡스톤 범위 충족)
- **우리 시스템 적합도:** 성능 최대화 + 컨텍스트 길이가 결정적인 시나리오(약관 비교 모드·과제 2 EDI lookup 통합)에서 ①보다 우위
- **권장 양자화:** FP4 (NVFP4) → 약 36GB, 약 8~10 tok/s

### 4.3 ③ Qwen3-32B — 모던하고 균형 잡힌 선택

- **개발사:** Alibaba Qwen Team, 2025 공개
- **강점:**
  - Qwen2.5의 후속, **하이브리드 reasoning 모드** 지원 (필요 시 reasoning ON, RAG에서는 OFF로 컨텍스트 충실도 우선)
  - 한국어 능력 Qwen2.5 대비 추가 개선
  - 128K 컨텍스트, 32B 사이즈 → DGX Spark에 FP8로 안정적
  - 명령 추종 ★★★★★ (IFEval 강함)
- **약점:**
  - 릴리스가 비교적 신규 → 한국어 벤치마크 평가 사례가 ① ②보다 적음. 도입 시 사내 회귀 테스트 필수
- **우리 시스템 적합도:** ①의 한국어 강점 + ②의 컨텍스트·명령 추종을 절충하는 균형 선택. **검증 충분히 하면 ①의 대안**
- **권장 양자화:** FP8 (32GB)

### 4.4 ④ Solar-Pro-2-22B-Preview — 한국 회사 도메인 친화

- **개발사:** Upstage (한국 기업)
- **강점:**
  - 한국어 비즈니스 도메인 최적화. Solar 시리즈는 *효율적 사이즈 대비 강한 성능* 노선
  - 한국 기업 → 사내 도입·기술 지원·라이선스 협의 친화적
  - 22B → DGX Spark에 매우 여유. 동시 사용자 늘어도 안정
- **약점:**
  - 32B/70B 대비 절대 성능에서는 한 단계 아래 (특히 다중 hop 추론, 표 정합성)
  - Preview 버전 → 안정성·후속 업데이트 정책 확인 필요
- **우리 시스템 적합도:** *국내 회사 모델*이라는 정책적 강점. 한국 보험 약관 도메인 fine-tuning 진행 가능성 시 협력 친화
- **권장 양자화:** FP16 (44GB) 또는 FP8 (22GB)

### 4.5 ⑤ Llama-3.3-70B-Instruct — 생태계 호환성 최강

- **개발사:** Meta, 2024-12 공개
- **강점:**
  - 70B 클래스 SOTA, 명령 추종 우수
  - 128K 컨텍스트
  - **생태계가 가장 풍부** — TensorRT-LLM, vLLM, AWQ·GPTQ·EXL2 등 모든 양자화·서빙 도구 1차 지원. NVIDIA가 DGX 시리즈에 Llama 모델군 최적화 사례 풍부
  - 라이선스: Llama 3 Community License, 사내·상업 사용 OK (월 활성 7억 미만 한도)
- **약점:**
  - **한국어가 1순위 학습 언어가 아님** → ①②③④에 비해 한국어 격식체·법률체 표현 정확도 약간 떨어짐
  - 한국어 fine-tune 변형(Llama-3.3 Bllossom 등 커뮤니티)이 등장하면 보완 가능
- **우리 시스템 적합도:** 모델 자체보다 *NVIDIA 최적화 친화성*이 큰 매력. 운영 안정·툴체인 성숙도가 결정적 변수일 때 선택
- **권장 양자화:** FP4 (35GB) → 약 7~9 tok/s

### 4.6 ⑥ HyperCLOVA X SEED-14B — 한국어 특화 경량 후보

- **개발사:** Naver, 2025 공개

  - 라이선스: HyperCLOVA X SEED는 사내·연구용은 무료지만 *상업 운영 조건 확인 필수*
- **우리 시스템 적합도:** **속도 우선 시나리오**(퀵 코드 검색 모드) 전용 모델로 ① 또는 ② 옆에 *듀얼 모델 운영* 가능

### 4.7 ⑦ Gemma-3-27B-IT — 멀티모달 가능

- **개발사:** Google DeepMind, 2025-03 공개

- **우리 시스템 적합도:** 과제 2 단일 모델로 텍스트 RAG + 이미지 OCR/Vision 보조 두 작업을 묶고 싶을 때 유력

### 4.8 ⑧ Mistral Small 3.2-24B-Instruct — 라이선스 친화·효율적

  - 24B → DGX Spark에 FP16으로 적재 가능
- **약점:**
  - 한국어 학습 비중이 다국어 모델 중 *상대적으로 낮음* — 한국어 격식체 정확도 ①②③④ 대비 차이
- **우리 시스템 적합도:** **라이선스 제약이 가장 중요한 경우** 1순위 후보. 한국어 보강을 위해 약관 도메인 fine-tune 진행 자유 (Apache-2.0)

## 5. 추천 — 1·2순위 + 시나리오별 가이드

### 5.1 종합 1순위 — **EXAONE-3.5-32B-Instruct (FP8)**

- 한국어 SOTA + 32B 클래스로 DGX Spark에 가장 *균형 잡힌 적재*
- 알파에서 이미 EXAONE 7.8B로 운용 중 → 시스템 프롬프트·평가셋 재사용 가능, 마이그레이션 비용 최소
- 사내 보험 도메인에 가장 자연스러운 격식체 한국어 출력

### 5.2 종합 2순위 — **Qwen2.5-72B-Instruct (FP4/NVFP4)**

- 절대 성능 최대화. 한국어 + 다국어 + 128K 컨텍스트 + 명령 추종 ★★★★★
- 약관 비교 모드·GraphRAG 결합·과제 2 EDI 통합 등 *컨텍스트 길이가 결정적*인 시나리오에서 ①을 능가
- 도입 시 KV 캐시 운용 정책(top-K, num_ctx) 튜닝 필요

### 5.3 시나리오별 선택 매트릭스

### 5.4 듀얼 모델 운영 옵션

DGX Spark의 128GB 메모리는 *32B 모델 2개를 동시 로드*하기에 충분하다.

- **A안 (단일)** — ① EXAONE-3.5-32B 단일 운용. 단순·안정·알파 호환.
- **B안 (듀얼)** — ① EXAONE-3.5-32B (일반/약관 정형) + ⑥ HyperCLOVA X SEED-14B (퀵 코드). 메모리 32+28=60GB
- **C안 (최고 성능)** — ② Qwen2.5-72B 단일 (FP4)

권장: **A안 도입 → 1차 사용 데이터 후 B/C안 검토**

# 270. 개발자 Fixback 및 탈모 약관 근거 응답 구현 보고서

## 목적

- 수술종수 질의가 GraphDB 안내 문구 때문에 심평원 수가표를 잘못 덧붙이지 않도록 경계를 보완한다.
- 실제로 기동하지 않은 LLM이 사용자 화면에 선택지나 현재 상태로 노출되지 않도록 유지한다.
- 탈모 관련 질의에서 일반적인 `탈모`를 곧바로 보상 제외로 확정하지 않고, 선택한 실손 세대의 직접 약관 조항과 필요한 추가 확인 사항을 함께 제시한다.

## 구현 내용

### 1. 수가 조회 및 용어 보정 Fixback

- 심평원 수가 직접 조회는 GraphDB 컨텍스트가 아니라 **사용자 질문의 명시적 수가 의도**로만 시작한다.
- `수가`, `수가코드`, `심평원`, `수가표`, `점수`, `수술코드` 또는 `Q2861`, `AA157` 같은 수가 코드 형식은 허용한다.
- `N39.3`처럼 점을 포함하는 ICD 진단코드만으로는 수가 조회를 시작하지 않는다.
- GraphDB 컨텍스트는 조회가 이미 허용된 뒤 수술명·수가 코드 보강에만 사용한다.
- `술먹고`, `술마시고`, `술 먹고`, `술 마시고`는 독립 음주 표현으로 인식한다. 반면 `수술`, `절제술`, `폐쇄술`, `이식술`의 접미사 `술`은 음주 후 상해로 보정하지 않는다.

### 2. 실행 중인 LLM 표시 정합성

- 설치된 Ollama 모델 목록과 실제 메모리에 기동 중인 모델 목록을 분리했다.
- 로그인·채팅·관리자 화면은 실제 실행 중인 모델만 기본 선택지와 상태 표시에 사용한다.
- 브라우저에 남은 이전 모델 선택값이 현재 실행 중 목록에 없으면 활성 기본 모델로 안전하게 복원한다.
- 사용자 문구는 `기동 중인 LLM`으로 통일하며, EXAONE 7.8B의 정적 예시를 제거했다.

### 3. 탈모 약관 근거 응답

- 온톨로지 원본 매니페스트에 다음 판단 차원을 추가했다.
  - 노화현상으로 인한 탈모
  - 의사 진단 질병성 탈모
  - 치료·약물 부작용 탈모
  - 치료·미용 목적
  - 업무 또는 일상생활 지장 여부
  - 급여/비급여 구분
- 보험 지식 값은 코드 상수가 아니라 온톨로지의 `source_grounded_decision` 프로필에 둔다. 이 프로필은 4세대 자사 약관의 직접 조항과 5세대 표준약관의 직접 조항을 각각 지정한다.
- 선택한 세대를 검색 필터와 재정렬 경로에 전달한다. 오래된 인덱스에 없는 세대 메타데이터는 원본 청크 메타데이터에서 읽기 전용으로 보완한다.
- 직접 약관 조항이 검색되면 해당 조항을 canonical 판단 결과로 승격한다. GraphDB의 일반 `추가 검토` 경로는 이 직접 근거를 무효화하지 않는다.
- 일반 `탈모 보상 가능?` 및 질병·치료 부작용 문맥은 `추가 확인 필요`로 처리한다. 노화성 면책 조항을 자동 적용하지 않으며, 보상 가능도 자동 확정하지 않는다.
- 노화현상으로 인한 탈모 문맥은 `조건부 보상 제외 조항 확인`으로 표시한다. 비급여 여부와 업무·일상생활 지장 여부를 별도 조건으로 명시한다.
- 사용자 화면은 내부 식별자 대신 한국어 상태, 적용 조건, 직접 조항 근거, 추가 확인 질문, 확인할 자료를 렌더링한다.
- canonical 결과가 있는 스트림은 생성 중 임시 모델 템플릿을 먼저 내보냈다가 최종 결과에서 사라지지 않도록 버퍼링한다. 기존 Graph 패널 중복 제거 동작은 유지한다.

## 운영 반영 전제와 남은 위험

- 이번 작업은 `concepts.json` 원본 매니페스트에 후보 지식을 추가했지만, 운영 active manifest와 GraphDB는 변경하지 않았다. 실제 앱의 기본 활성 온톨로지에 반영하려면 기존 실무자 승인 흐름으로 후보를 검토한 뒤 manifest 적용과 GraphDB 재빌드를 별도 수행해야 한다.
- 직접 조항 기반 canonical 판단은 현재 탈모 범위에 한정한다. 다른 약관 판단으로 확대할 때도 코드 분기를 늘리기보다, 실무자 승인된 온톨로지 프로필과 직접 근거 청크를 추가해야 한다.
- 로컬 macOS Python 환경에는 API 테스트에 필요한 `aiosqlite`가 없어 FastAPI 범위는 DGX 가상환경에서 검증했다. 패키지 설치나 운영 LLM 설정 변경은 수행하지 않았다.
- Git stage, commit, push는 수행하지 않았다.

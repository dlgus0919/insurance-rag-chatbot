# Chrome 스모크 결함 근본 원인 분석

- 대상 버전: `ba214da` (`fix(chat): enforce grounded final answers`)
- 범위: 2026-07-21 Chrome 스모크의 MRI 속성 답변과 식도조루술 복합 질의
- 변경 여부: 분석만 수행했으며, 운영 코드·활성 계산 규칙·온톨로지·GraphDB는 변경하지 않았다.

## 결론

두 결함은 로컬 LLM의 성능 또는 응답 변동으로 설명되지 않는다. 두 경로 모두 모델 응답이 생성되기 전에 결정형 코드가 최종 말풍선을 만들거나 모델 생성을 건너뛴다. 따라서 정식 전체 UAT는 보류한다.

## 1. MRI 연간 보상한도 답변

### 재현 증거

질문 `4세대 자기공명영상진단(MRI/MRA)의 연간 보상한도는?`은 `policy_attribute_lookup`으로 분류된다. 실제 `약관_ch_002441`의 직접 선택 창에는 자기공명영상진단의 공제금액 `1회당 3만원`과 보상한도 `300만원`이 구분되어 있다.

그러나 직접 속성 hit의 본문에는 인접한 도수치료·주사치료 행까지 포함된 넓은 OCR 창이 전달된다. 같은 결정형 답변을 코드 수준에서 재현하면 숫자 목록이 `3만원, 350만원, 250만원, 300만원` 등을 함께 포함하고, 표시 함수가 금액 단위 숫자 중 앞의 두 값을 선택해 `3만원, 350만원`을 반환한다. Chrome 말풍선과 일치한다.

5세대도 동일하다. 직접 근거에는 `1회당 5만원` 공제와 `200만원` 연간 한도가 함께 있으나, 표시 함수는 두 값을 구분하지 않는다. 또한 같은 세대의 두 증거 행이 있으면 행 수만으로 "비교 결과" 형식이 선택되어 중복 또는 무관 행이 노출된다.

### 원인

1. 직접 속성 검색기가 선택한 값 주변의 `display_evidence`를 만들지만, 후속 조항 행 추출은 그 값을 사용하지 않고 넓은 `document`를 다시 분해한다.
2. `_public_clause_detail_numbers`는 연간 한도 질의에서 공제금액과 한도를 의미적으로 구분하지 않고 금액 단위 숫자 두 개를 앞 순서대로 선택한다.
3. `_build_clause_detail_evidence_answer`는 서로 다른 비교 축이 아니라 단순히 두 행이 존재한다는 이유로 비교 형식을 선택한다.

## 2. 식도조루술 수가 코드와 실손 보상 여부

### 재현 증거

원문 심평원 청크 `심평원_ch_000915`에는 `Q2333 식도조루술 Esophagostomy`가 있고, GraphDB에도 `HAS_MEDICAL_FEE_CODE`로 `Q2333` 연결이 있다.

그럼에도 `식도조루술 수가 코드와 실손 보상 여부를 알려줘`의 수가명 직접 추출 결과는 빈 목록이다. 현재 HIRA 수가명 정규식은 `이식수술·이식술·수술·절제술·폐쇄술·치료·검사`로 끝나는 명칭만 인식하며 `조루술`을 포함하지 않는다.

질의는 `quickcode`이면서 `requires_coverage_judgment=True`로 분류된다. `resolve_specialized_coverage_disposition`이 이 복합 질의 전체를 보상판단으로 처리해 `coverage_insufficient` 텍스트를 반환하고, 스트리밍 라우트가 그 텍스트를 즉시 출력한다. 따라서 코드 검색 결과 또는 코드 미확인 안내 어느 쪽도 최종 말풍선에 남지 않는다.

### 원인

1. 수가명 추출이 제한된 어미 정규식에 의존해 원문·GraphDB에 있는 수가명을 찾지 못한다.
2. 안전 게이트가 복합 질의를 "수가 정보"와 "보상 판단"으로 분해하지 않아, 보상 판단의 안전한 보류가 독립적인 수가 정보 답변까지 덮어쓴다.

## 최소 수정 계획

### A. 속성값 렌더링을 선택된 근거 값에 고정

1. 직접 속성 hit에 선택한 값과 값의 의미 축(예: `annual_limit`, `deductible`)을 명시적으로 보존한다.
2. 결정형 답변은 넓은 OCR 청크를 재분석하지 않고, 해당 선택 값과 좁은 근거 창만 사용한다.
3. 단일 세대 질의는 같은 세대 행이 여러 개여도 비교 형식으로 바꾸지 않는다. 비교 형식은 명시적 비교 축이 둘 이상인 경우에만 사용한다.
4. 실제 OCR처럼 인접 시술·공제·한도가 섞인 fixture로 회귀 테스트를 추가한다. 4세대 MRI의 연간 한도 질의에서 `300만원`만, 5세대에서 `200만원`만 출력되는지 검증한다.

### B. 복합 수가·보상 질의를 분리해 조합

1. 수가명은 특정 어미 나열이 아니라 "명칭 + 수가/점수" 구조를 추출한 뒤, 심평원 원문 또는 확인된 `HAS_MEDICAL_FEE_CODE`와 정확히 대조해 검증한다.
2. 수가 정보 컴포넌트는 확인된 원문 행이 있으면 코드와 출처를, 없으면 "수가코드를 확인하지 못했다"는 사실만 표시한다.
3. 보상 판단 컴포넌트에는 현재의 fail-closed 규칙을 그대로 적용한다. 확인된 수가 코드나 표준코드의 보상 의견을 근거 없이 보상 판단으로 승격하지 않는다.
4. 두 컴포넌트를 한 최종 답변에 순서대로 조합한다. 예: `Q2333` 수가 정보 + "실손 보상 여부는 직접 보장·면책 조항만으로 확정 불가".
5. 이 경로는 LLM을 호출하지 않는 회귀 테스트를 추가해, 코드 정보가 안전 게이트 때문에 소실되지 않음을 검증한다.

## UAT 기준

수정 후 다음 조건이 모두 충족될 때만 정식 전체 UAT를 시작한다.

- 4세대·5세대 단일 MRI 연간 한도 질의가 각각 공제금액·타 시술 한도·중복 없이 올바른 한도만 제시한다.
- 비교 질의만 비교 형식으로 표시되고, 각 세대의 직접 근거가 함께 제시된다.
- 식도조루술 복합 질의가 `Q2333`과 심평원 출처를 표시하면서 보상 판단은 안전하게 보류한다.
- 6개 Chrome 스모크를 재실행해 최종 말풍선과 PDF 이동을 확인한다.

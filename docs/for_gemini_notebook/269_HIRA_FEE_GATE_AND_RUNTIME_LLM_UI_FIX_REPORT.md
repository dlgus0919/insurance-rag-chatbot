# 269. 수가 조회 게이트 및 실행 중 LLM UI 정합성 수정 보고서

## 목적

- 수술종수 질의가 GraphDB 안내 문구의 `코드` 때문에 심평원 수가표를 잘못 추가하지 않도록 한다.
- 설치만 된 Ollama 모델을 실제로 기동 중인 모델처럼 로그인, 채팅, 관리자 화면에 표시하지 않도록 한다.

## 구현

### 1. 심평원 수가 조회

- 직접 수가 조회 여부는 GraphDB 컨텍스트가 아니라 사용자 질문만으로 판정한다.
- `수가코드`, `수가`, `심평원`, `수가표`, `점수`, `수술코드`, 실제 코드 형식이 있는 질의만 조회를 허용한다.
- 조회가 허용된 뒤에만 GraphDB 컨텍스트에서 수술명과 코드를 보강한다.
- 한 글자 별칭 `술`은 독립된 음주 표현일 때만 매칭한다. 따라서 `수술`, `절제술`, `폐쇄술`, `이식술`의 접미사는 음주 후 상해로 보정되지 않는다.

### 2. 실행 중인 LLM 표시

- Ollama 설치 목록(`/api/tags`)과 현재 메모리에 올라온 모델(`/api/ps`)을 분리했다.
- 로그인과 채팅의 모델 선택 API, 관리자 시스템 요약은 실행 중인 모델 목록만 사용한다.
- 브라우저에 남은 이전 모델 값이 현재 선택지에 없으면 활성 기본 모델로 복원하고, 선택 출처를 기본값으로 되돌린다.
- 사용자 화면 문구를 `기동 중인 LLM`으로 통일하고, 정적 EXAONE 예시와 관리자 원시 설정값 노출을 제거했다.

## 검증

- Python 변경 범위: `86 passed`
- DGX 격리 작업공간의 FastAPI 포함 변경 범위: `101 passed, 1 warning`
- 프런트엔드 Node 회귀: `5 passed`
- 프런트엔드 번들 빌드: 성공
- 정적 검색: 프런트엔드의 `exaone3.5:7.8b`, `AI 모델 선택`, `활성 모델` 노출 0건

전체 pytest는 `902 passed, 1 failed`였다. 실패한 `test_claim_calculation_route_returns_payable_amount`는 이번 변경과 무관한 보험금 계산 공제값 기대치 불일치이며, 수정 전 DGX 메인 저장소에서도 동일하게 재현됐다. 본 패치에서는 범위 밖 계산 로직을 변경하지 않았다.

## 범위와 남은 확인

- LLM 서버의 기본값, 기동 상태, 모델 파일은 변경하지 않았다.
- 실제 브라우저 동작은 API와 프런트엔드 회귀 테스트로 대체 검증했다. 운영 브라우저에서 다음 기동 시 로그인 화면과 관리자 시스템 탭이 현재 SGLang 또는 vLLM 모델만 표시하는지 확인하면 된다.

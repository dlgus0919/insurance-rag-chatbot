## 3. 콘텐츠 타입 분류 정책

각 청크는 다음 두 메타로 분류한다.

### 3.1 `content_type` (콘텐츠 분류)

| 값          | 의미                       | 저장 형식                                                                     |
| ----------- | -------------------------- | ----------------------------------------------------------------------------- |
| `text`    | 본문 텍스트                | 일반 청크                                                                     |
| `table`   | 표                         | JSON(헤더·행) + 직렬화 텍스트 청크 + 원본 PNG                                |
| `image`   | 그림·도식                 | 이미지 파일 + 캡션 텍스트 청크 (bbox·페이지 메타)                            |
| `formula` | 수식·특수기호             | raw 텍스트 청크                                                               |
| `noise`   | 밑줄·필기·페이지 번호 등 | **저장하지 않음** (제거 후 메타에 `noise_removed=True` 카운트만 보존) |

### 3.2 `source_method` (추출 방식)

| 값              | 의미                          |
| --------------- | ----------------------------- |
| `native`      | PDF 텍스트 레이어 직접 추출   |
| `ocr_paddle`  | PaddleOCR + PP-Structure      |
| `ocr_clova`   | Naver CLOVA OCR               |
| `ocr_upstage` | Upstage Document Parse        |
| `vision_llm`  | Vision LLM 기반 표·도식 캡션 |
| `manual`      | 수동 입력·교정               |

### 3.3 노이즈 정의 (저장 금지)

- 밑줄 (geometric line, 텍스트 없음)
- 필기 (handwritten stroke, 텍스트 외 변동성 큰 픽셀 패턴)
- 페이지 번호·머리글·바닥글 (반복 패턴 감지)
- 워터마크 (반투명 반복 텍스트)

이들은 OCR 후처리에서 제거하되, 제거 통계(페이지별 noise pixel ratio)만 메타에 기록.

## 4. 통합 DB 스토리지 설계 (1차 안)

다양한 형식 데이터를 단일 DB에 욱여넣지 않고, **3종 스토리지 + 1종 객체 저장**으로 분리.

```
┌──────────────────────────────────────────────────────────────────┐
│                     통합 보험 보상 DB                              │
├──────────────────────────────────────────────────────────────────┤
│ ① VectorDB — Chroma                                              │
│   · 모든 텍스트 청크 (text/table-serialized/image-caption)        │
│   · BGE-M3 임베딩, 메타: doc_*, content_type, source_method, ... │
│   · 검색용 핵심                                                   │
├──────────────────────────────────────────────────────────────────┤
│ ② GraphDB — Neo4j Community (또는 알파 PoC: NetworkX 인메모리)    │
│   · 노드: 보험사·상품·약관·조항·보장종목·표준코드(std_cd)·면책   │
│   · 엣지: 보상함·보상안함·정의함·해당함·면책함·개정됨           │
│   · 다중 hop 추론, 환각 방지의 결정론적 근거                       │
├──────────────────────────────────────────────────────────────────┤
│ ③ 관계형 DB — SQLite (또는 DuckDB)                                │
│   · `nonpay_standard` 테이블: 비급여 표준 모델 529,022 행          │
│   · `documents` 테이블: 원본 문서 카탈로그                         │
│   · `chunk_index` 테이블: chunk_id ↔ graph_node_id ↔ std_cd      │
│   · 정확 매칭 lookup, 통계용                                      │
├──────────────────────────────────────────────────────────────────┤
│ ④ 객체 저장 — 파일시스템                                           │
│   · `data/raw/` 원본 PDF (gitignore)                              │
│   · `data/extracted/<doc_id>/{text,tables,images}/` OCR 결과      │
│   · `data/index/{chroma,bm25,graph}/` 산출 인덱스                 │
└──────────────────────────────────────────────────────────────────┘
```

### 4.1 핵심 통합 키와 매핑

- `chunk_id` (Vector·BM25·GraphDB·SQLite 모두 보유) — 모든 답변·출처의 최소 단위
- `std_cd` (비급여 표준 코드) — 약관 청크·그래프 노드·SQLite 행을 잇는 의료 식별자
- `clause_id` = `<doc_id>:<조문번호>:<항>` (그래프 노드 식별자)
- `node_id` (그래프 내부 식별자, chunk_id와 1:1 또는 1:N)

### 4.2 환각 방지 메커니즘

1. **출처 강제**: 모든 답변은 `chunk_id` 또는 `clause_id`를 인용해야만 표시. LLM이 출처 없이 단정하면 후처리에서 차단·재생성
2. **그래프 결정론**: "보상 가능 여부" 같은 판정은 GraphDB 쿼리 결과를 우선 사용. LLM은 자연어 정리만 담당
3. **신뢰도 표기**: OCR 청크는 `confidence`, 추론 결과는 `evidence_strength` 메타로 사용자에게 노출
4. **컨텍스트 외 답변 차단**: SYSTEM_PROMPT에서 "컨텍스트에 없는 정보는 '확인 안 됨'으로 답하라" 규칙 강화 + 평가에서 "환각률" 측정

### 4.3 확장성 고려

- VectorDB: 청크 ID에 `doc_id` 프리픽스 → 신규 약관 추가 시 충돌 방지
- GraphDB: Cypher 스키마에 `version` 속성 → 약관 개정 시 버전 분기 가능
- 관계형 DB: 마스터 데이터(D8)는 `apply_start_date`/`apply_end_date`로 시점 추적
- 객체 저장: `data/extracted/<doc_id>/manifest.json`에 추출 메타·해시 → 재처리 시 변경 감지

# RAG 챗봇 추가 기능 구현 계획서 (Plan v2)

> **작성:** 기획자
> **작성일:** 2026-05-04
> **기반 상태:** M12 완료 (인증·내보내기·로깅까지 적용된 Streamlit 알파)
> **대상 마일스톤:** M13 — M15 (M15는 1차 사용 결과 분석 후 진행, 본 계획서에서는 아이디어 수준만 기록)

---

## 1. 배경

알파 v1 단일·하이브리드 RAG로 챗봇이 동작하고 있으며 사내 임직원 운용을 위한 인증·로깅·내보내기까지 들어간 상태입니다 (M12). 이 위에 사용자(현장 운영자)가 요청한 다음 세 가지 추가 기능을 얹어 **실무 효율**을 끌어올립니다.

1. Top-K · 온도 자동 설정 로직
2. 카테고리/문서 필터 + 검색 모드 옵션 (퀵 코드 검색, 약관 정형 검색)
3. 출처 PDF 페이지 미리보기 + 파일 열기

이 중 (1)은 알파 v1의 1차 사용 결과를 충분히 누적·분석한 뒤에 진행하기로 결정. 이 계획서에서는 큰 그림만 둡니다. 본 스프린트의 실제 구현 범위는 (2)와 (3)이며, M13 → M14 두 단계로 분할합니다.

## 2. 사용자 결정 사항 (확정)

| 항목 | 결정 |
|---|---|
| UI 진입 방식 | 채팅 입력창 위에 "검색 모드" 라디오/토글, 사이드바에 "검색 대상 문서" 체크박스. 단일 페이지 유지. |
| 약관 정형 폼 | 3종 모두 구현 (보상가능 여부 판정 / 약관 조문 검색 / 키워드·시술명 검색) |
| PDF 미리보기 | PNG 이미지 렌더링 + macOS `open` 기반 파일 열기 링크 병행 |
| 퀵 코드 상세 옵션 | 분류·점수·산정지침 요약, 실손 약관 기준 보상가능 여부 (관련 코드 안내는 알파 범위 외) |

## 3. 기능별 설계

### 3.1 검색 대상 문서 카테고리 필터 (사이드바)

기존 사이드바의 "LLM 모델 / Top-K / 온도 / 대화 초기화" 아래에 새 섹션을 추가한다.

```
검색 대상 문서
[v] 심평원
[v] 약관
[v] 가이드북
```

- 기본값: 3개 모두 ON
- 0개 선택 시 안내 표시("최소 1개 문서를 선택해주세요") 및 검색 차단
- 검색 모드(3.2)와 연동되어, 모드 변경 시 카테고리 기본값이 자동 조정되며, 사용자가 그 위에서 추가/삭제 가능

내부 구현 포인트:
- `RagPipeline.retrieve_hits(..., doc_filter: list[str] | None = None)` 인자 추가
- `VectorStore.query` / `query_with_filter`에 `where={"doc_short": {"$in": [...]}}` 전달
- BM25는 인덱스 메타에 `doc_short`를 보존해 두고 hit 후 post-filter
- 현재 `Hit.metadata`에 `doc_short`가 들어 있는지 확인 후 없으면 `BM25Index.build` 시점에 메타 기록 (M13 작업)

### 3.2 검색 모드 (채팅 입력 영역 위)

`st.radio` 또는 세그먼트 컨트롤로 노출.

```
검색 모드: ( ) 일반 질의   ( ) 퀵 코드 검색   ( ) 약관 정형 검색
```

모드별 입력 폼·프롬프트·카테고리 기본값이 다름. 모드는 **세션 상태**로만 보관하며, 모드 전환 시 입력 값은 초기화한다.

#### 3.2.1 일반 질의 (기존 동작)
변경 없음. `st.chat_input` 그대로.

#### 3.2.2 퀵 코드 검색
- **입력:** 시술/수술명 단일 텍스트 (예: `식도조루술`)
- **옵션 체크박스 2종:**
  - `[v] 분류·점수·산정지침 요약` (기본 ON)
  - `[ ] 실손 약관 기준 보상가능 여부` (기본 OFF)
- **카테고리 자동 매핑:**
  - 보상가능 여부 OFF → 심평원만
  - 보상가능 여부 ON → 심평원 + 약관
- **Top-K:** 6 (코드 라우팅이 강하므로 더 적게 — 응답 속도↑)
- **시스템 프롬프트:** 모드 전용. 짧고 단단하게 코드 우선 추출 → 옵션이 켜진 항목만 추가 정보를 한 응답에 포함.
- **답변 형식 (예시):**
  ```
  [코드] Q2333 — 식도조루술
  [분류 / 점수] 자233-1 / 1,452.18점
  [산정지침 요약] (옵션 ON 시) ...
  [보상] (옵션 ON 시) 실손 약관 보장 가능, 다만 ...
  [출처: 심평원, p.531] [출처: 약관, p.38]
  ```
- **LLM 호출:** 1회. 옵션 토글에 따라 프롬프트의 "포함할 정보" 섹션만 동적 구성.

#### 3.2.3 약관 정형 검색
서브 라디오로 3종 시나리오 중 1개 선택.

| # | 시나리오 | 입력 폼 | 동작 |
|---|---|---|---|
| ① | 보상가능 여부 판정 | 진단코드 또는 시술명, 보장종목 다중 체크박스 [질병급여/질병비급여/3대비급여], 상황 메모 | "보상하지 않는 사항" 조항 우선 검색. 보장종목별로 가/불가/조건부 명시 답변. |
| ② | 약관 조문 검색 | 키워드 / 조문번호 옵션 / 별표 포함 체크 | 조문 단위로 retrieve, 본문 + 인용 |
| ③ | 키워드·시술명 검색 | 키워드 (부분일치 허용) | 시술명·용어 청크 우선. 동의어 보강. |

- **카테고리 자동 매핑:** 약관만 강제, 사용자가 추가 가능
- **Top-K:** 8 (기본)
- **시스템 프롬프트:** 시나리오별 전용 (예: ①은 "보장종목별로 명시", ②는 "조문 인용 형식 준수")

### 3.3 PDF 페이지 미리보기 + 파일 열기

기존 출처 expander 안 각 청크 카드에 두 개의 액션 버튼을 추가한다.

```
1. [심평원] | BZ20…pdf | p.531
   제2부 제9장 ...
   ┌──────────────┬────────────┐
   │ 페이지 미리보기 │ PDF 열기 │
   └──────────────┴────────────┘
   (미리보기 ON 시 PNG 이미지 표시)
```

기술 결정:
- 렌더링: PyMuPDF(`fitz`)로 해당 페이지를 150 DPI PNG로 추출
- 캐시: `@st.cache_data(max_entries=64)`로 (pdf_path, page_no) 키 캐시. 메모리 폭주 방지를 위해 LRU 64개 한도
- 파일 열기: `subprocess.Popen(["open", pdf_path])` — macOS 한정. 다른 OS는 안내 메시지("이 기능은 macOS에서만 동작합니다")
- 멀티페이지 청크: `page_start`만 표시, 청크가 2페이지 이상 걸치면 prev/next 버튼 추가 (옵션, M14에서 구현)

위험: PDF 자료가 큰 경우(1,429페이지) PyMuPDF 페이지 렌더 시 첫 호출 ~200~500ms. 캐시 후 즉시. 파일 열기 버튼은 **로컬 단일 사용자 가정**임을 README에 명시.

### 3.4 (M15 — 보류) Top-K · 온도 자동 설정

알파 v1·M13·M14의 누적 사용 로그(`logs/chat_*.jsonl`)를 분석한 뒤 진행. 현 단계는 아이디어 정리만:

- **접근 1 — 질의 분류기:** 질의를 [코드조회/사실조회/요약/판정] 4 라벨로 분류 후 라벨별 사전 정의된 (top_k, temperature) 매핑. 분류기는 작은 LLM call 또는 룰베이스(코드 패턴, 의문사 패턴) 모두 후보.
- **접근 2 — 검색 점수 분포 기반:** RRF 후 1위~2위 점수 격차가 크면 top_k=4로 감소(확신 높음), 격차가 작으면 top_k=10으로 증가. 코드성 질의에 효과적.
- **온도:** 정확한 코드/숫자 요구 → 0.0~0.1, 일반 설명 요구 → 0.2~0.3. 시스템 프롬프트만으로 충분히 통제 가능하면 굳이 자동화하지 않음.
- **결정 가이드:** 1차 테스트 로그를 30케이스 이상 모은 뒤 어떤 자동화가 실제로 도움이 되는지 평가. 효과가 미미하면 미구현.

## 5. 위험 및 완화

| 위험 | 영향 | 완화 |
|---|---|---|
| 카테고리 필터로 retrieve 결과가 0건이 되는 케이스 | 답변 실패 | "선택 문서 내에 관련 정보가 없습니다." 명시. 사용자가 카테고리 확장하도록 UI 안내 |
| 퀵 모드 시 코드를 못 찾을 때 일반 모드와 같은 폴백 동작 필요 | UX 혼란 | 코드 미발견 시 "정확한 코드를 찾지 못했습니다 — 일반 질의 모드를 사용해 보세요" 안내 |
| PDF 페이지 렌더링 메모리 누수 | 장시간 사용 시 메모리 ↑ | `cache_data(max_entries=64)`, `fitz.open` 후 명시적 `close()` |
| `subprocess.Popen(["open", ...])`의 OS 의존 | macOS 외 환경에서 실패 | `sys.platform` 분기 + 안내. 알파 운용은 macOS 한정 README 명시 |
| 약관 정형 보상판정 답변의 법적 표현 정확도 | 잘못된 안내 위험 | 모든 답변 하단에 "본 답변은 검색 보조이며 최종 판정은 약관 원문과 사내 절차에 따릅니다." 고지 자동 부착 |

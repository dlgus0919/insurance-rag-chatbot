## 1) 감사 범위 및 방법

감사 대상 문서:
- `실무가이드` (manifest 기준 328p)
- `상담사례집` (manifest 기준 350p)

감사 방식:
1. **문서 전체 구간 균등 샘플링**(4분위) + 민감 앵커 페이지 포함
2. 각 샘플 페이지의 **원본 페이지 이미지**를 PDF에서 재렌더
3. 같은 페이지의 OCR 산출물(`manifest blocks`, `text/*.txt`, `tables/*.json`)과 직접 대조
4. 정량 지표 + 수작업 시각 검토를 함께 반영

생성 산출물:
- 샘플 목록: `reports/ocr_audit_full/sample_pages.json`
- 원본 이미지: `reports/ocr_audit_full/images/<doc>/pXXX_original.png`
- 상세 블록 분석: `reports/ocr_audit_full/audit_details.json`

## 4) 원본 대조 주요 관찰 (수작업 시각 검토)

## 4-1. 실무가이드

양호:
- p064, p068, p074: 수술종수표 헤더/행/종수 컬럼 구조 유지 양호
- p123, p288: 복합 표/텍스트 혼합에서도 주요 행·숫자 유지
- p206, p256: 본문형 페이지 텍스트 가독성 양호

하자:
- p064 텍스트 블록에서 본문 제목 일부 오인식  
  예: `사지골(연양)`, `100,000`, `29/01/2019` 등
- p297(목차성 페이지)에서 하단 쓰레기 토큰 유입  
  예: `1 Shares`, `Year`, `ELEC`, `CORP`
- p041 일부 표에서 헤더가 본문 문장으로 붕괴(`p040_t01.json`)하는 구조 왜곡

판정:
- **수술종수 핵심 표 영역은 실사용 가능 수준**
- 다만 텍스트 블록(제목/목차/장식영역)에서 국소 오인식이 반복됨

## 4-2. 상담사례집

양호:
- 본문형 텍스트 페이지(p044, p131, p220, p311, p322 등)는 읽기 품질 양호
- 일부 실제 표(p102, p257)는 핵심 컬럼 구조 유지

하자(중요):
- 법령/판례 인용 박스를 표로 오인식  
  (`p021_t00.json`, `p171_t00.json`, `p220_t00~t03.json` 등)
- 장문 단일 헤더 테이블이 다수 생성되어 구조화 품질 저하
- 결과적으로 table JSON의 검색 신호가 약해지고, 불필요한 table chunk 증가

판정:
- **텍스트 OCR은 양호, 표 검출 정확도는 취약**
- 특히 상담사례집은 “표가 아닌 박스형 인용문”에 대한 table false-positive가 핵심 하자

---

## 5) 종합 품질 판정

최종 판정: **조건부 적합 (Partially Acceptable)**

- 강점:
  - 핵심 업무표(실무가이드 수술종수표/장해표)의 구조 보존은 대체로 양호
  - retrieval recall@8 관점에서 검색 누락은 낮음
- 취약:
  - 텍스트 블록 OCR의 국소적 오인식(특수문자/숫자/목차 구간)
  - 상담사례집의 table false-positive 과다(구조화 품질 저하)

즉, “완벽히 인식” 상태는 아니며, **문서 유형별 후처리 정책 분리**가 필요합니다.

## 6) 우선 개선 권고 (데이터 품질 관점)

1. 상담사례집 table 블록 정밀 필터링
- 단일 컬럼 + 장문 헤더 + 법령문 패턴 표는 table에서 text로 다운캐스트
- rows=0/실질 셀구조 부재 표 제거

2. 목차/장식 영역 노이즈 억제
- 짧은 영문 토큰 반복(`Shares/Year/...`) 제거 규칙 추가
- 페이지 하단/상단 장식 영역 우선 제외

3. 실무가이드 제목행 보정
- `연골/관절`류 도메인 어휘 사전 기반 후처리로 오인식 교정

## 7) 재빌드/재실행 필요 여부

### 7-1. 이번 감사 자체를 위해
- 추가 OCR 전체 재실행은 **필수 아님** (현 산출물로 감사 완료)

### 7-2. 품질 개선 반영을 실제 지표에 확인하려면
- 후처리 규칙 반영 후 **재인제스트 + eval 재실행 필요**

장시간 명령(이번 턴 미실행):
1. `python scripts/run_full_ocr.py --doc all --yes`
2. `python scripts/ingest.py --include-ocr --stage all`
3. `HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 RERANKER_ENABLED=false OLLAMA_TEMPERATURE=0 python scripts/eval.py --ocr`

## 8) 결론

원본 이미지 대조 결과, 현재 OCR 파이프라인은 **핵심 업무표 활용에는 유효**하나,  
문서 전체 품질 기준으로는 특히 상담사례집의 table 구조화 품질이 아직 미완성입니다.

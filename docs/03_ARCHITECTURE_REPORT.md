# 보험 문서 RAG 챗봇 — 아키텍처 보고서

**작성일:** 2026-05-06
**작성:** 캡스톤 프로젝트 팀(김범준)
**대상:** 내부 이해관계자

---

## 1. 프로젝트 요약

건강보험 고시·실손보험 약관·보상가이드북 등 사내 보험 문서를 AI가 읽고, 보험사 직원의 자연어 질문에 **문서 근거를 인용하며 정확하게 답변**하는 로컬 전용 RAG 챗봇입니다. 외부 클라우드 AI API를 전혀 사용하지 않아 민감 문서가 사외로 유출될 위험이 없습니다.

---

## 2. 시스템 구성 개요

```
[PDF 문서 3종]
      │
      ▼
┌─────────────────────────────────────────────────────┐
│  전처리 파이프라인 (scripts/ingest.py)               │
│                                                     │
│  ① PDF 텍스트 추출 (pdfplumber → PyMuPDF 폴백)      │
│  ② 계층 인식 청킹  (편/부/장/절 메타데이터 보존)    │
│  ③-A Dense 임베딩  (BAAI/bge-m3 → ChromaDB 저장)    │
│  ③-B BM25 인덱스   (kiwipiepy 형태소 분석 → pkl 저장)│
└─────────────────────────────────────────────────────┘
              │ (1회 실행 후 인덱스 영속)
              ▼
┌─────────────────────────────────────────────────────┐
│  RAG 추론 파이프라인  (src/rag/pipeline.py)          │
│                                                     │
│  [질문 입력]                                        │
│      │                                              │
│      ├─→ Dense 검색  (BGE-M3 임베딩 + ChromaDB)     │
│      ├─→ 키워드 검색 (BM25 + 한국어 형태소)          │
│      │         │                                    │
│      └─→ RRF 융합  (두 결과를 순위 기반으로 합산)   │
│                │                                    │
│                └─→ Reranker (BGE-reranker-v2-m3)    │
│                         │                           │
│                         ▼                           │
│               [컨텍스트 청크 최대 8개]               │
│                         │                           │
│               Ollama 로컬 LLM 호출                  │
│               (기본: exaone3.5:7.8b)                │
│                         │                           │
│               [답변 + 출처 자동 인용]                │
└─────────────────────────────────────────────────────┘
              │
              ▼
┌─────────────────────────────────────────────────────┐
│  Streamlit UI  (src/ui/streamlit_app.py)            │
│  - 임직원 비밀번호 인증                              │
│  - 채팅 말풍선 + 출처 expander                      │
│  - 모델/Top-K/온도 사이드바 설정                    │
│  - 검색 대상 문서 카테고리 필터 (사이드바)           │
│  - 검색 모드: 일반/퀵 코드/약관 정형 검색           │
│  - PDF 페이지 미리보기 + 파일 열기                  │
│  - 대화 내보내기 (TXT / CSV / JSON)                 │
│  - 감사 로그 (logs/chat_YYYY-MM-DD.jsonl)           │
└─────────────────────────────────────────────────────┘
```

## 3. 주요 컴포넌트 상세

### 3.1 입력 문서 (현재 3종)

| 문서 식별자 | 파일명                                                      | 설명                                                                   |
| ----------- | ----------------------------------------------------------- | ---------------------------------------------------------------------- |
| 심평원      | BZ202603053039374.pdf                                       | 건강보험 행위 급여·비급여 목록표 및 급여 상대가치점수 (1,400+ 페이지) |
| 약관        | 2.약관_신한 이지로운 실손의료보험(무배당)_20260401_0325.pdf | 신한 실손보험 약관                                                     |
| 가이드북    | 보상가이드북.pdf                                            | 사내 보상 가이드북                                                     |

문서 종류를 추가하려면 `src/config.py`의 `PDF_SOURCES` 목록에 한 줄 추가하면 됩니다.

---

### 3.2 PDF 파싱 (`src/parser/pdf_parser.py`)

pdfplumber로 1차 텍스트 추출을 시도하고, 결과가 비어 있거나 라이브러리가 없으면 PyMuPDF로 자동 전환합니다. 추출에 실패한 페이지는 빈 문자열로 처리하되 경고 로그를 남겨 추적이 가능합니다.

---

### 3.3 계층 인식 청킹 (`src/parser/chunker.py`)

한국어 법령·약관 문서의 고유한 계층 구조를 청크 메타데이터에 보존합니다.

**청킹 우선순위**

1. 절(節) 단위로 분리 — 새로운 제N절이 시작되면 이전 버퍼를 독립 청크로 저장
2. 빈 줄(\n\n) 단위로 분리 — 절이 없거나 너무 긴 경우
3. 슬라이딩 윈도우 (기본: 800자, 오버랩 100자) — 여전히 긴 경우

**저장되는 메타데이터**

| 필드                  | 예시 값                      |
| --------------------- | ---------------------------- |
| doc_short             | 심평원, 약관, 가이드북       |
| volume                | 제1편 …                     |
| part                  | 제1부 …                     |
| chapter               | 제2장 기본진료료             |
| section               | 재진 진찰료                  |
| page_start / page_end | 101 / 103                    |
| codes                 | ["AA157", "AA100", "A9900"]  |
| is_code_table         | true (코드 5개 이상 포함 시) |

문서 유형별로 헤더 패턴이 다르게 적용됩니다. 고시 문서는 `제N편/부/장/절`을, 약관은 `제N관`, `제N조(…)`, `[별표N]`을 인식합니다.

---

### 3.4 임베딩 (`src/retrieval/embedder.py`)

**BAAI/bge-m3** 다국어 임베딩 모델을 사용합니다. 한국어·영어·의료 코드가 혼재하는 보험 문서에 특히 적합하며 로컬 캐시에서만 로드하여 외부 네트워크 호출이 없습니다. 모든 벡터는 L2 정규화 후 저장합니다.

---

### 3.5 벡터 저장소 (`src/retrieval/vector_store.py`)

ChromaDB를 로컬 디스크(`data/index/chroma/`)에 영속 저장합니다. 코사인 유사도 검색을 기본으로 하며, **코드 필터 검색**(`query_with_filter`) 기능이 추가로 구현되어 있습니다.

코드 필터 검색: 질문에 의료 코드(예: `AA157`, `N39.3`)가 포함된 경우, 해당 코드가 메타데이터에 명시된 청크를 우선 검색해 검색 정밀도를 높입니다. 코드 표 행에 정확히 일치하는 경우 코사인 점수에 +0.25 보너스를 부여합니다.

---

### 3.6 BM25 키워드 검색 (`src/retrieval/bm25.py`)

한국어 형태소 분석기 **kiwipiepy**로 명사·동사·외국어 토큰을 추출해 BM25Okapi 인덱스를 구성합니다. kiwipiepy 설치가 없는 환경에서는 정규식 기반 토큰화로 자동 대체됩니다. 인덱스는 `data/index/bm25.pkl`에 영속 저장됩니다.

---

### 3.7 하이브리드 검색 — RRF 융합 (`src/retrieval/hybrid.py`)

Dense 검색(의미 기반)과 BM25 검색(키워드 기반)의 결과를 **Reciprocal Rank Fusion(RRF)**으로 합산합니다.

```
score(문서) = Σ { 1 / (60 + 해당검색에서의순위) }
```

두 방법 모두에서 높게 나온 청크가 최종 점수가 높아지므로, 단순 코드 조회와 의미 검색 모두에서 안정적인 결과를 냅니다.

---

### 3.8 Reranker (`src/retrieval/reranker.py`)

**BAAI/bge-reranker-v2-m3** 크로스인코더로 RRF 후보군을 재정렬합니다. Cross-encoder는 질문과 문서를 쌍으로 입력해 더 정밀한 관련도를 계산합니다. 환경 변수 `RERANKER_ENABLED=false`로 비활성화 가능하며, 모델 로드 실패 시 자동으로 비활성화되어 서비스가 계속 작동합니다.

---

### 3.9 RAG 파이프라인 전체 흐름 (`src/rag/pipeline.py`)

하나의 질문이 들어오면 아래 6단계가 순서대로 실행됩니다.

1. **쿼리 전처리** — 동의어 확장(예: 3대비급여 관련 질문에 관련 용어 추가), 의료 코드 패턴 추출, 명칭-코드 질의 감지
2. **Dense 검색** — 질문 임베딩 → ChromaDB 코사인 검색 (기본 Top-12)
3. **BM25 검색** — kiwipiepy 토큰화 → BM25 점수 (기본 Top-12)
4. **RRF 융합 + 필터링** — 넓은 페이지 범위의 저품질 청크(목차 등) 자동 제거 후 Top-16 후보 선택
5. **Reranker** — 크로스인코더로 Top-8 최종 선별
6. **LLM 생성** — Ollama로 프롬프트 전달, 스트리밍 답변 반환, 출처 자동 보강

---

### 3.10 LLM 클라이언트 (`src/llm/ollama_client.py`)

Ollama HTTP API(`/api/generate`)를 통해 로컬 LLM을 호출합니다. 스트리밍과 일괄 생성 모두 지원하며, 서버 미연결·모델 미설치 시 한국어 안내 메시지로 에러를 반환합니다. 기본 모델은 `exaone3.5:7.8b`이며 환경 변수 `OLLAMA_MODEL`로 교체 가능합니다.

지원 모델 후보 목록 (`config.OLLAMA_CANDIDATE_MODELS`): exaone3.5:7.8b, exaone3.5:7.8b-instruct, timHan/llama3korean8B4QKM:latest (llama-3-Korean-Bllossom-8B Q4_K_M), qwen2.5:7b·14b-instruct, gemma3:4b·1b

UI에서는 Ollama `/api/tags` 응답을 실시간으로 조회해 실제로 설치된 모델만 드롭다운에 표시합니다. 커뮤니티 네임스페이스 모델(예: `timHan/…`)은 Ollama API가 `:latest` 태그를 붙여 반환하므로 후보 목록에도 `:latest`를 포함해야 합니다.

---

### 3.11 프롬프트 설계 (`src/llm/prompt.py`)

시스템 프롬프트 6개 규칙: 컨텍스트 한정 답변, 불확실 시 고백, 코드 정확 매핑, 표 행 단위 해석, 보상 여부 명확 판단, 문서명 인용(심평원/약관/가이드북).

Few-shot 예시가 프롬프트에 내장되어 있어 소형 LLM에서도 출처 형식이 안정적으로 출력됩니다.

---

### 3.12 Streamlit UI (`src/ui/streamlit_app.py`)

임직원 전용 채팅 인터페이스로, 다음 기능을 제공합니다.

- **인증**: `APP_PASSWORD` 환경 변수로 비밀번호 보호 (미설정 시 공개)
- **모델 선택**: 사이드바에서 Ollama 설치 모델 자동 감지 후 선택
- **파라미터 조정**: Top-K(4~12), 온도(0~0.7) 슬라이더
- **검색 대상 문서 필터**: 사이드바 체크박스로 심평원/약관/가이드북 개별 선택 (0개 선택 시 차단)
- **검색 모드**: 일반 질의 / 퀵 코드 검색 / 약관 정형 검색 3종 라디오 전환
- **스트리밍 답변**: 토큰 단위 실시간 표시
- **출처 expander**: 각 답변 아래에 참조 청크 메타데이터·본문 미리보기 + PDF 페이지 미리보기·파일 열기 버튼
- **대화 내보내기**: TXT · CSV · JSON 형식

---

### 3.13 감사 로그 (`src/utils/logger.py`)

모든 접근·로그인·질문·답변·내보내기 이벤트를 `logs/chat_YYYY-MM-DD.jsonl` 파일에 기록합니다. 90일 로테이션으로 자동 관리되며, 각 로그 항목에는 타임스탬프·세션ID·이벤트 유형·세부 정보가 포함됩니다.

---

### 3.14 퀵 코드 검색 모드 (`src/rag/quick_code.py`)

시술·수술명을 입력하면 심평원 코드(예: Q2333, AA157)와 분류·점수·산정지침을 빠르게 조회합니다. Top-K를 6으로 축소해 응답 속도를 높이며, 옵션에 따라 실손 약관 보상가능 여부도 함께 제공합니다. 모드 전용 시스템 프롬프트로 코드 우선 추출 형식을 강제하고, 보상가능 여부 옵션 ON 시 카테고리 필터를 심평원+약관으로 자동 확장합니다.

---

### 3.15 약관 정형 검색 모드 (`src/rag/insurance_form.py`)

약관 관련 3종 시나리오를 구조화된 입력 폼으로 처리합니다.

| 시나리오 | 입력 | 동작 |
|----------|------|------|
| ① 보상가능 여부 판정 | 진단코드/시술명 + 보장종목 체크박스 | "보상하지 않는 사항" 조항 우선 검색, 보장종목별 가/불가/조건부 명시 |
| ② 약관 조문 검색 | 키워드/조문번호 | 조문 단위 retrieve, 본문+인용 |
| ③ 키워드·시술명 검색 | 키워드 (부분일치) | 시술명·용어 청크 우선, 동의어 보강 |

모든 답변 하단에 "본 답변은 검색 보조이며 최종 판정은 약관 원문과 사내 절차에 따릅니다." 고지가 자동 부착됩니다.

---

### 3.16 PDF 페이지 미리보기 (`src/ui/pdf_view.py`)

출처 expander의 각 청크 카드에서 해당 페이지를 PNG 이미지로 렌더링합니다. PyMuPDF(`fitz`)로 150 DPI 추출하고, `@st.cache_data(max_entries=64)` LRU 캐시로 반복 렌더링 비용을 제거합니다. `subprocess.Popen(["open", pdf_path])`로 macOS 기본 PDF 뷰어에서 파일을 직접 열 수 있으며, macOS 외 환경에서는 안내 메시지를 표시합니다.

  ▼

        │

                                        │
                                        ▼
                                [스트리밍 답변 + 출처]

## 7. 보안 및 운영 특이사항

**완전 로컬 처리**: PDF 원문, 임베딩 벡터, LLM 추론 모두 사내 서버(개발 단계에서는 M4 Mac)에서 실행됩니다. 외부 AI API 호출이 없어 문서 내용이 사외로 전송되지 않습니다.

**인증**: `APP_PASSWORD` 환경 변수로 단순 비밀번호 인증을 제공합니다. 현재는 알파 수준이며, 운영 전 SSO 연동이 권장됩니다.

**감사 추적**: 모든 질문과 답변이 세션 ID, 타임스탬프와 함께 기록되어 사후 감사가 가능합니다.

**환경 의존**: Ollama 데스크톱 앱 또는 `ollama serve` 실행이 전제 조건입니다. LLM 모델 파일(수 GB)은 별도 다운로드가 필요합니다.

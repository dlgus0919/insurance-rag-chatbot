# 264. DGX 사내 시연 시나리오 가이드

작성일: 2026-07-06

## 목적

이 문서는 2026-07-05 DGX 리허설에서 검증한 사용 흐름을 실제 사내 시연자가 따라 할 수 있는 순서로 정리한 가이드다. 튜토리얼 문서나 화면 캡처 자료를 만들 때도 이 흐름을 기본 목차로 사용할 수 있다.

리허설 결과 원문은 `docs/263_DGX_DEMO_REHEARSAL_REPORT.md`에 있다.

## 시연 전 준비

### 1. 운영 상태 확인

DGX에서 다음 상태가 준비되어 있어야 한다.

```text
app: 127.0.0.1:18080
llm: 127.0.0.1:30000/v1
model: qwen3-next-80b-a3b-instruct-fp8
tmux: insurance-rag-api, sglang-local
```

운영자는 DGX에서 상태를 확인한다.

```bash
/srv/ai-ops/bin/insurance-rag-status --json
```

정상 기준:

- `ok=true`
- `api_health=ok`
- `api_models=ok`
- `sglang=ok`
- `ollama=ok`
- `vllm=warn`은 SGLang 시연 경로에서는 허용
- `default_bm25`, `default_chroma`, `v2_bm25`, `combined_bm25`, `graph_db`, `standard_db`, `users_json`이 `ok`

### 2. Mac 접속 터널

시연자는 Mac에서 터널을 연다.

```bash
ssh -N -L 18080:127.0.0.1:18080 <authorized-dgx-user>@<dgx-host>
```

브라우저에서 접속한다.

```text
http://localhost:18080
```

### 3. 시연 계정

실제 시연 전 사용할 계정과 비밀번호를 별도로 확인한다. 리허설에서는 live `users.json`을 수정하지 않았고, fixture 계정인 `user/user1234`, `admin/admin1234`는 DGX 운영 사용자 파일에서 실패했다.

시연 계정이 불확실하면 운영자가 사전에 계정을 확인하거나 reset한다. 비밀번호는 문서나 화면에 노출하지 않는다.

## 전체 시연 구성

권장 순서:

1. 접속 및 로그인
2. 모델 상태 확인
3. 일반 RAG 질의
4. 보험금 계산
5. 계산 결과 기반 후속 질문
6. 세션 목록 및 내보내기
7. 관리자 화면 확인
8. 마무리 메시지

전체 시연 시간은 10~15분 정도로 잡는다.

## 시나리오 1. 접속 및 로그인

### 목표

사용자가 사내망 또는 터널을 통해 앱에 접속하고, 로그인 기반 업무 앱으로 진입하는 흐름을 보여준다.

### 진행

1. 브라우저에서 `http://localhost:18080` 접속
2. 로그인 화면 확인
3. 시연용 일반 사용자 계정으로 로그인
4. 채팅 화면으로 이동하는지 확인

### 설명 포인트

- 이 앱은 단순 공개 데모가 아니라 로그인 기반 업무 앱이다.
- 사용자 역할에 따라 일반 채팅/계산 기능과 관리자 기능 접근이 구분된다.

### 기대 결과

- 로그인 후 채팅 화면이 열린다.
- 일반 사용자에게는 관리자 기능이 노출되지 않거나 접근이 제한된다.

## 시나리오 2. 모델 상태 확인

### 목표

현재 답변 생성 모델이 DGX 로컬 LLM으로 연결되어 있음을 보여준다.

### 진행

1. 채팅 화면의 모델 선택 영역을 확인한다.
2. 기본 로컬 모델이 다음 값인지 확인한다.

```text
sglang:qwen3-next-80b-a3b-instruct-fp8
```

3. 필요하면 운영자가 API로도 확인한다.

```bash
curl -fsS http://127.0.0.1:18080/api/system/models
```

### 설명 포인트

- 현재 시연 기본 경로는 SGLang + Qwen3 Next 80B Instruct다.
- Ollama `exaone3.5:7.8b`는 로컬 fallback 후보로 남아 있다.
- vLLM은 동시에 띄우지 않았으므로 상태 점검에서 `warn`이어도 이번 시연 실패가 아니다.

## 시나리오 3. 일반 RAG 질의

### 목표

약관 기반 질문에 대해 근거 문서를 검색하고, 출처와 함께 답변하는 흐름을 보여준다.

### 입력 예시

```text
실손 약관의 3대비급여 항목을 모두 알려주세요.
```

### 기대 답변 핵심

답변에는 다음 항목이 포함되어야 한다.

- 도수치료
- 체외충격파치료
- 증식치료
- 비급여 주사료
- 비급여 자기공명영상진단, MRI, MRA

리허설에서는 source 4건이 반환됐다.

### 설명 포인트

- 답변은 모델 지식만으로 생성하는 것이 아니라 검색 근거를 바탕으로 생성한다.
- 출처가 함께 표시되므로 실무자는 답변 뒤의 근거를 확인할 수 있다.
- 일반 질의의 기본 인덱스는 `v2_only` 계열로, 보정본 OCR 데이터가 포함된다.

### 튜토리얼 캡처 포인트

- 질문 입력 전 화면
- 답변 생성 중 상태
- 최종 답변
- 출처 badge 또는 근거 영역

## 시나리오 4. 보험금 계산

### 목표

실무자가 청구 항목과 금액을 입력했을 때 구조화 계산 결과와 검토 필요 상태를 함께 확인하는 흐름을 보여준다.

### 입력 예시

| 필드 | 값 |
| --- | --- |
| 청구 항목명 | 도수치료 |
| 표준코드 | MX122 |
| 청구금액 | 150000 |
| 수량 | 1 |
| 분류 힌트 | 3대비급여 |
| 방문 구분 | 통원 |
| 실손 세대 | 4세대 |

### 기대 결과

리허설 기준 결과:

```text
총 청구금액: 150000원
예상 지급금액: 105000원
예상 공제금액: 45000원
calculation_status: estimated_review_required
requires_review: true
```

### 설명 포인트

- `MX122` 표준코드를 명시하면 자동 산정 예시를 안정적으로 보여줄 수 있다.
- 항목명만 입력하고 표준코드가 없으면 `blocked_missing_info`로 보류될 수 있다. 이는 오답을 내는 대신 정보 부족을 표시하는 현재 정책이다.
- `requires_review=true`는 계산 결과를 바로 최종 지급 결정으로 확정하지 말고 실무 검토가 필요하다는 의미다.

### 튜토리얼 캡처 포인트

- 계산 입력 폼
- 계산 결과 카드
- 지급액/공제액
- 검토 필요 문구
- 적용 근거 또는 basis 영역

## 시나리오 5. 계산 결과 기반 후속 질문

### 목표

계산 결과가 채팅 세션에 저장된 뒤, 사용자가 같은 세션에서 후속 조건을 물었을 때 기존 계산 스냅샷을 활용하는 흐름을 보여준다.

### 선행 조건

시나리오 4의 도수치료 계산을 먼저 수행한다.

### 입력 예시

```text
도수치료를 보상하지 않는다면 얼마인가요?
```

### 기대 답변 핵심

리허설 기준 응답:

```text
기존 예상 지급금액 105,000원에서 해당 항목 지급액 105,000원을 제외해 예상 지급금액은 0원입니다.
```

### 설명 포인트

- 사용자가 같은 사안을 이어서 질문하면 이전 계산 결과를 맥락으로 사용한다.
- 새로운 검색 질의가 아니라 계산 스냅샷 기반 후속 계산으로 처리될 수 있다.
- 조건 변경 시 금액이 어떻게 달라지는지 빠르게 확인할 수 있다.

### 튜토리얼 캡처 포인트

- 계산 결과가 남아 있는 세션
- 후속 질문 입력
- 지급액 0원으로 재해석된 답변

## 시나리오 6. 세션 목록 및 내보내기

### 목표

업무 중 생성된 질의와 계산 결과가 세션으로 남고, 기록을 다시 확인하거나 내보낼 수 있음을 보여준다.

### 진행

1. 좌측 또는 세션 목록 영역을 연다.
2. 일반 RAG 질의 세션을 확인한다.
3. 보험금 계산 세션을 확인한다.
4. 필요하면 `JSON`, `CSV`, `TXT` 내보내기 중 하나를 실행한다.

### 리허설 결과

- 일반 RAG 질의 세션: 2 messages, sources 포함
- 보험금 계산 세션: 4 messages, sources 포함

### 설명 포인트

- 세션 기록은 실무 검토, 재현, 교육 자료 제작에 사용할 수 있다.
- 내보내기에는 공개 가능한 source 정보와 처리 경고가 포함될 수 있다.

### 튜토리얼 캡처 포인트

- 세션 목록
- 계산 세션 복원 화면
- 내보내기 메뉴
- export 파일 예시 일부

## 시나리오 7. 관리자 화면 확인

### 목표

관리자가 운영 상태, 인덱스, 사용자, GraphDB 상태를 확인하는 흐름을 보여준다.

### 진행

1. 일반 사용자 로그아웃
2. 시연용 관리자 계정으로 로그인
3. 관리자 화면으로 이동
4. 시스템 상태 확인
5. 사용자 목록 확인
6. GraphDB sync 상태 확인

### 기대 결과

리허설 기준 관리자 확인값:

```text
system status: ok
chunks: true
graph: true
relational: true
users: true
indices: default, v2_only, v1_v2_combined
GraphDB available: true
graph_nodes: 545223
graph_edges: 46241
```

### 설명 포인트

- 관리자 화면은 사용자가 답변을 생성하는 화면이 아니라 운영 상태와 데이터 준비 상태를 보는 화면이다.
- 인덱스와 GraphDB가 준비되어 있어야 실무 질의에서 근거 기반 답변 품질을 기대할 수 있다.
- 사용자 관리 화면에서는 계정 상태를 확인할 수 있으나, 비밀번호나 민감 정보는 표시하지 않는다.

### 튜토리얼 캡처 포인트

- 관리자 진입 화면
- 시스템 상태 카드
- 인덱스 준비 상태
- 사용자 목록
- GraphDB 상태

## 시연 중 말할 수 있는 핵심 메시지

- 이 앱은 DGX 로컬 LLM과 사내 보유 문서 인덱스를 연결한 업무용 RAG 앱이다.
- 일반 질의는 약관/실무 문서 근거를 찾아 답변하고, 출처를 함께 보여준다.
- 보험금 계산은 지급액을 단정하는 도구가 아니라, 표준코드와 약관 근거를 바탕으로 예상 금액과 검토 필요 사유를 보여주는 보조 도구다.
- 불확실한 입력은 억지로 계산하지 않고 보류하거나 검토 필요로 남긴다.
- 관리자 화면에서는 모델, 인덱스, 사용자, GraphDB 상태를 확인할 수 있다.

## 시연 중 피해야 할 것

- 테스트 fixture 계정(`user/user1234`, `admin/admin1234`)을 그대로 쓰겠다고 말하지 않는다.
- LLM 답변을 최종 지급 결정처럼 설명하지 않는다.
- `requires_review=true`를 오류로 설명하지 않는다. 실무 검토 필요 상태다.
- vLLM `warn`을 전체 장애로 설명하지 않는다. 이번 시연 경로는 SGLang이다.
- 비밀번호, API 키, 사용자 개인정보를 화면에 노출하지 않는다.

## 문제 발생 시 빠른 대응

실무자가 화면 오류·검토 상태를 안전하게 분류하고 이관할 때는
[실무자 전체 운영 오류 대응 매뉴얼](266_PRACTITIONER_OPERATIONS_TROUBLESHOOTING_MANUAL.md)을 먼저 확인한다.
아래 내용은 DGX 운영 담당자와 시연 준비 담당자의 추가 확인 절차다.

### 로그인 실패

- 시연 계정이 DGX live `users.json`에 있는지 확인한다.
- 비밀번호는 문서에 쓰지 말고 운영자가 reset한다.

### 모델 목록에 Qwen SGLang이 보이지 않음

운영자가 확인한다.

```bash
/srv/ai-ops/bin/insurance-rag-status --json
curl -fsS http://127.0.0.1:30000/v1/models
```

필요 시 운영 wrapper로 재기동한다.

```bash
/srv/ai-ops/bin/insurance-rag-up --provider sglang --model qwen3-next-80b-a3b-instruct-fp8 --replace
```

### 보험금 계산이 보류됨

- `MX122` 표준코드를 입력했는지 확인한다.
- 방문 구분이 `통원`, 실손 세대가 `4세대`인지 확인한다.
- 표준코드 없이 항목명만 넣은 경우 보류가 정상일 수 있다.

### 세션 export가 비어 있음

- 스트리밍 답변이 끝까지 완료됐는지 확인한다.
- 브라우저에서는 답변 생성이 끝난 뒤 세션 목록을 다시 연다.
- API 테스트 스크립트에서는 `done` 이벤트 직후 연결을 끊지 말고 EOF까지 읽는다.

## 튜토리얼 문서 제작용 목차

튜토리얼은 다음 구조로 만들면 된다.

1. 접속 방법
2. 로그인
3. 모델 선택 확인
4. 일반 약관 질의하기

6. 보험금 계산 입력하기

8. 후속 질문하기
9. 세션 다시 보기
10. 기록 내보내기
11. 관리자 상태 확인
12. 자주 발생하는 문제

## 필수 fixback

### 1. P1 후보 release 권한

attempt3의 release root/monitor/graph/ontology/reports가 `2775`, 다수 파일이 `664`다. 구현 보고서의 group-write 없음 주장과 불일치한다.

요구사항:

- 새 attempt4 최종 산출물과 build evidence root에서 group/world write를 제거한다.
- 내부 검토용 최소 기준은 디렉터리 `2750`, 파일 `640`이다.
- 모든 생성·검증·snapshot 작업이 끝난 뒤 마지막 단계에서 hardening한다.
- `find <attempt4-root> -perm /022 -print` 결과는 비어야 한다.
- 검토 그룹은 읽기/탐색만 가능하고 write는 불가능해야 한다.

### 2. P1 Graph source provenance

attempt3 외부/DB 내부 manifest의 `chunks_path`가 이미 삭제된 `/tmp/tmpkd9k2a6g.jsonl`을 가리킨다. 명시한 `active_source_chunks_path`도 존재하지 않는다.

요구사항:

- 임시 materialized JSONL 경로를 publication manifest에 기록하지 않는다.
- 실제 입력인 canonical document manifest와 선택적 active overlay를 안정적 descriptor로 기록하고 각각 SHA-256을 포함한다.
- CLI에 active overlay 경로를 명시했으면 존재하지 않을 때 build 전에 fail-closed한다. overlay가 의도적으로 없으면 인자를 생략하고 manifest에 명시적 empty/absent 상태를 기록한다.
- 외부 Graph manifest와 DB 내부 manifest가 동일해야 한다.
- release verify에서 기록된 필수 source path 존재성과 SHA-256 일치를 검사해 mismatch/missing을 거부한다.
- 기존 manifest 소비자와 관리자 API 계약을 깨지 않는 최소 변경으로 구현한다.
- stable source descriptor가 반영된 새 attempt4 전체 Graph를 재빌드한다.

### 3. P2 SQLite sidecar 및 읽기 전용 도구

attempt3의 현재 `-wal`/`-shm`은 Review Team의 일반 `mode=ro` 연결이 만든 것으로, Developer 최종 원본 산출물 결함으로 소급하지 않는다. 다만 publication 후보에는 남길 수 없다.

요구사항:

- snapshot/후보 검증 경로는 SQLite URI `mode=ro&immutable=1`을 사용한다.
- Graph build connection을 완전히 닫고 필요한 checkpoint를 완료한다.
- 마지막 검증 후 `insurance_graph.sqlite-wal`, `insurance_graph.sqlite-shm`이 없어야 한다.
- 이후 immutable 검증을 다시 수행해 integrity `ok`, foreign-key violation 0, counts/manifest/hash 일치를 확인한다.
- 일반 runtime store의 동시성 의미를 불필요하게 바꾸지 않는다. 후보 snapshot/verification 경로만 최소 보정한다.

### 4. P2 frontend lockfile 버전

`frontend/package.json`은 `1.2.0`이지만 `frontend/package-lock.json`의 top-level 및 `packages[""]`는 `1.0.0`이다.

요구사항:

- lockfile 두 version 필드를 `1.2.0`으로 정렬한다.
- dependency graph 및 resolved/integrity 항목 diff는 없어야 한다.
- README, frontend config, dist, package, lockfile의 버전 표기를 재검증한다.

### 5. P2 JSONL 전체 행 검증

`_canonical_document_manifest_path()`가 첫 유효 JSON object를 읽은 즉시 반환해 후속 malformed 행을 검증하지 않는다.

요구사항:

- EOF까지 모든 비어 있지 않은 행을 JSON object로 파싱한다.
- 적어도 한 행 존재 조건을 유지한다.
- 유효 첫 행 뒤 malformed JSON 또는 non-object 행이 있는 JSONL을 build 전에 거부한다.
- trailing malformed row 및 trailing non-object row 회귀 테스트를 추가한다.

# v1.2.0 일반 질의 온톨로지 릴리스 검증

## 결론

- 일반 질의용 온톨로지와 GraphDB 후보를 운영 safe-baseline으로 활성화했다.
- 사용자 표시 버전은 `1.2.0`이며, FastAPI OpenAPI 기술 계약 버전 `0.1.0`은 별도 값이므로 유지했다.
- 기존 보험금 계산 액티브 룰과 처리 정책은 변경하지 않았다.
- 운영 LLM은 재기동·전환하지 않고 `sglang:qwen3-next-80b-a3b-instruct-fp8`을 유지했다.
- 사용자 계정, 대화 이력, 로그 원본, RAW/OCR 문서는 이 작업에서 변경하거나 재수집하지 않았다.
- 구현과 런타임 검증은 통과했으며, 물리 GUI 실사용 테스트와 준비된 실무자 UAT 실행은 남은 작업이다.

## 진행 중 발견하고 처리한 사항

1. 외부 Graph manifest의 키만 순회하던 검증은 내부 manifest에만 추가된 키를 놓칠 수 있었다. 내부·외부 key-set을 양방향 비교하도록 fail-closed 회귀를 추가했고 Review Team 재검토가 PASS였다.
2. 활성화 전 보호 메인의 구형 active ontology에는 provenance가 없어 기본 registry가 stale 처리되며 focused 7건이 실패했다. 새 후보 manifest를 명시한 격리 환경에서 focused 158건과 전체 1,130건을 통과했고, 운영 활성화 후 55개 concept를 다시 확인했다.
3. Review Team의 첫 전체 검증 2건은 공유 `/tmp` lock 소유권 충돌이었다. 격리 lock 경로에서 전체 1,130건을 재실행해 통과했다.
4. 읽기 검증 과정에서 SQLite가 빈 WAL/SHM sidecar를 생성했다. 원본 attempt4는 변경하지 않았고 아직 미참조 상태였던 운영 복사본에서만 sidecar를 제거한 뒤 DB 해시, integrity, 권한, safe-baseline 검증을 다시 통과했다.
5. 원격 검증 스크립트의 셸 인용 실패는 명령이 실행되지 않아 상태 변경이 없었다. 실제 env/API/runtime/model 상태를 재확인한 뒤 중복 활성화 없이 재개했다.
6. UAT 초안에는 P0 반복 행이 실제 실행 큐로 펼쳐지지 않은 문제, 대시보드 게이트 누락·셀 겹침, KST 표시 변환 문제가 있었다. 75개 실행 행과 모든 게이트를 명시하고, 수식 오류 0건 및 7개 시트 렌더링을 재검증했다.

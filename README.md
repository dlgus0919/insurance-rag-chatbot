# 보험 문서 RAG 챗봇

> 약관과 업무 문서의 근거를 찾아 설명하고, 보험금 계산 검토를 보조하는 온프레미스형 업무 지원 애플리케이션입니다.

**현재 릴리스 태그: v1.1.0**

**master 검증 상태 (2026-07-15):** 실무자 전체 운영 오류 대응 매뉴얼과 관리자 GraphDB 핵심 구조 탐색 기능은 구현 및 자동 검증을 마쳤습니다. GraphDB 화면은 DGX 호스트의 headless Chromium과 LLM 동시 실행으로 검증했으며, DGX Spark 물리 데스크톱 브라우저에서의 최종 사용성 확인은 후속 운영 점검으로 남아 있습니다.

이 앱은 문서 근거를 빠르게 확인하고 계산 검토 과정을 정리하기 위한 도구입니다. 최종 지급 판단은 반드시 적용 약관, 계약 정보, 증빙 서류와 실무자 검토를 통해 확정해야 합니다.

## 무엇을 할 수 있나요?

- **일반 질의**: 약관, 실무가이드, 표준 코드, 상담 사례 등 등록된 문서를 검색해 근거와 함께 답변합니다.
- **문서 범위 지정**: 필요한 문서만 선택해 검색 범위를 좁힐 수 있습니다.
- **검색·답변 자동 설정**: 질문 유형과 검색 점수 분포를 바탕으로 검색 범위와 답변 생성 설정을 자동 조절합니다. 필요하면 설정에서 수동 조절로 바꿀 수 있습니다.
- **보험금 계산 보조**: 항목별 코드·명칭·금액을 입력하면 승인된 계산 룰과 문서 근거를 사용해 예상 결과를 만듭니다.
- **추가 확인 항목 표시**: 근거 또는 조건이 부족한 항목은 예상 지급액에 조용히 포함하지 않고, 결과와 적용 근거에서 별도로 강조합니다.
- **연속 업무 대화**: 같은 대화 스레드 안에서 계산 결과를 확인하고, 추가 확인 사항을 일반 질의로 물은 뒤, 확인된 조건을 반영해 다시 계산할 수 있습니다.
- **관리자 지식 확장**: 관리자는 새 문서를 등록하고, 자동 생성된 온톨로지·계산 룰 후보를 검토한 후 승인된 항목만 운영 지식에 반영할 수 있습니다.
- **관리자 GraphDB 탐색**: 전체 그래프를 브라우저로 전송하지 않고 핵심 노드 구조를 먼저 표시하며, 검색하거나 노드를 선택하면 상위 1단계와 제한된 하위 트리를 집중해서 확인할 수 있습니다.

## 빠른 사용 흐름

### 1. 앱 시작

바탕화면 실행기에서 모델과 앱을 준비합니다.

- `앱 상태: stopped`가 보이면 **모델 기동 선택**을 눌러 사용할 모델을 선택합니다.
- `앱 상태: <서버> (<모델명>) 실행 중`이 보이면 이미 실행 중인 모델을 유지해 앱을 열 수 있습니다.
- 준비가 끝나면 브라우저에서 로그인 화면이 열립니다.

실행기는 설치된 모델과 실제 실행 중인 모델을 구분합니다. 설치만 되어 있고 아직 로드되지 않은 모델은 “현재 실행 중인 모델 유지”로 표시하지 않습니다.

### 2. 일반 질의

1. **일반 질의**를 선택합니다.
2. 필요하면 입력창 위의 **문서 범위**에서 검색할 문서를 선택합니다. 선택하지 않으면 전체 활성 문서를 검색합니다.
3. 질문을 입력합니다.
4. 답변 아래의 참고 문서와 근거 내용을 확인합니다. 참고 항목에 마우스를 올리면 검색된 문서 조각을 바로 볼 수 있습니다.

검색/답변 자동 설정은 기본으로 켜져 있습니다. 검색 설정 버튼에서 끄면 Top-K와 온도를 직접 조절할 수 있습니다.

### 3. 보험금 계산 보조

1. **보험금 계산**을 선택합니다.
2. 실손 세대, 입원·외래 등 케이스 조건을 선택합니다.
3. 산정특례 여부는 **항목별이 아니라 계산 요청 전체에 한 번만** 선택합니다. 모르면 `모름`으로 두면 자동 지급 판단을 보수적으로 제한합니다.
4. 항목 코드 또는 명칭과 금액을 입력해 계산합니다.
5. 결과에서 예상 지급액, 항목별 계산, 적용 근거, 추가 확인 대상을 함께 확인합니다.

추가 확인 대상은 0원으로 숨기지 않습니다. 왜 자동 반영하지 않았는지와 어떤 근거가 더 필요한지가 결과에 표시됩니다. 확인이 끝난 뒤에는 같은 스레드에서 “이 항목을 보상한다면 다시 계산해줘”처럼 조건을 명시해 후속 계산을 요청할 수 있습니다. 조건이나 대상 항목이 모호하면 앱이 확인 질문을 먼저 제시합니다.

## 계산 결과를 해석하는 방법

| 결과 상태 | 의미 | 다음 행동 |
| --- | --- | --- |
| 예상 지급액 반영 | 승인된 룰과 입력 조건이 충족되어 계산에 포함됨 | 적용 근거와 금액을 검토 |
| 추가 확인 대상 | 약관 조건, 산정특례 여부, 항목 분류 또는 근거가 부족함 | 표시된 확인 사유를 검토하고 조건을 보완 |
| 계산 불가/보류 | 활성 룰 또는 필수 입력이 부족해 자동 계산하지 않음 | 관리자 또는 실무 검토 후 룰·근거·입력을 보완 |

보험금 계산은 LLM이 금액을 임의 생성하는 방식이 아닙니다. 승인된 활성 룰, 원문 근거, 표준 코드와 입력값을 해석하는 결정적 계산 경로를 사용합니다.

현재 기본 지원 범위는 4세대와 5세대 실손 계산 룰입니다. 이후 세대는 문서 근거와 실무자 승인 절차를 거쳐 활성 룰에 추가해야 하며, 미승인 세대의 지급 판단을 자동으로 확대하지 않습니다.

## 관리자: 새 문서와 지식 확장

관리자 페이지의 **지식 확장** 탭은 신규 문서를 운영 지식으로 반영하기 위한 검토 흐름입니다.

1. 새 문서를 추가합니다.
2. 시스템이 파일 형식과 PDF 텍스트 레이어를 확인합니다.
3. 스캔본처럼 텍스트 레이어가 없는 PDF는 경고와 함께 중단됩니다. 현재 이 경로에서 OCR을 자동 실행하지 않습니다.
4. 처리 가능한 문서에서는 온톨로지·계산 룰 후보가 생성됩니다.
5. 관리자가 후보의 설명, 원문 근거, 적용 대상과 위험 정보를 보고 승인·보류·거절합니다.
6. 승인된 항목만 **승인 항목 반영** 작업을 통해 활성 지식, 검색 인덱스, 관계형 연결 정보에 반영합니다.

기존 활성 계산 룰은 같은 화면에서 조회하고, 변경 사유를 남겨 수정할 수 있습니다. 신규 보험 지식이나 지급 판단이 승인 없이 자동으로 활성화되지는 않습니다.

## 관리자: GraphDB 탐색

관리자 페이지의 **GraphDB 탐색** 탭은 읽기 전용으로 동작합니다.

1. 기본 화면은 연결도가 높거나 상위 분류 역할을 하는 핵심 노드만 제한된 수로 표시합니다.
2. 개념 또는 별칭을 검색하거나 그래프의 노드를 선택하면 해당 노드로 확대됩니다.
3. 집중 보기에서는 상위 1단계와 제한된 하위 트리를 표시하며, 필요할 때만 일반 연관 관계를 포함합니다.
4. WebGL을 사용할 수 없으면 키보드로 탐색할 수 있는 2D 관계 목록으로 자동 전환합니다.

이 화면은 노드·관계 편집이나 GraphDB 재빌드 기능을 제공하지 않습니다. 대형 허브의 관계는 서버 상한에 따라 일부만 표시될 수 있습니다.

## 오류가 발생했을 때

인증, 검색, 문서 반입, 보험금 계산, GraphDB 탐색 등 운영 중 오류가 발생하면 [실무자 전체 운영 오류 대응 매뉴얼](docs/266_PRACTITIONER_OPERATIONS_TROUBLESHOOTING_MANUAL.md)을 먼저 확인합니다. 실무자는 조회, 입력 재확인, 단일 재시도와 관리자 이관까지만 수행하며, 데이터 삭제·인덱스 재빌드·서버 재시작·모델 변경은 운영 담당자 승인 없이 실행하지 않습니다.

## 권한

- **사용자**: 일반 질의, 보험금 계산 보조, 자신의 대화 이력 확인과 내보내기를 사용할 수 있습니다.
- **관리자**: 사용자 기능에 더해 사용자 관리, 진단, 지식 확장, 후보 검토와 승인 반영을 수행할 수 있습니다.

## 근거와 안전 원칙

- 일반 질의는 보정된 OCR 데이터가 포함된 활성 검색 인덱스를 기본으로 사용합니다.
- 지급·면책·감액·한도·공제 등 보험 지식은 코드에 임의로 고정하지 않고, 원문 근거와 승인된 활성 룰에서 읽습니다.
- 새 문서, 온톨로지 후보, 계산 룰 후보는 모두 검토 가능한 후보 상태에서 시작합니다.
- LLM은 검색 보조와 설명 생성에 사용할 수 있지만, 최종 계산 규칙이나 지급 결론을 독자적으로 만들 수 없습니다.
- 원본 문서, 사용자 데이터, 인증 정보와 비밀값은 저장소에 커밋하지 않습니다.

## 구성

```text
FastAPI API + 정적 SPA
Hybrid RAG (BM25 + vector search + reranker)
GraphRAG / ontology / source-grounded active rules
관계형 표준 코드 데이터와 결정적 보험금 계산 엔진
관리자 승인 및 감사 로그
로컬 LLM 서버(SGLang, vLLM, Ollama)
```

## 개발 및 검증

개발 환경에서는 Python 3.11 이상과 사전 준비된 모델·인덱스가 필요합니다.

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python scripts/manage_users.py init
python -m uvicorn src.api.main:app --host 127.0.0.1 --port 8000
```

관련 변경은 먼저 좁은 범위의 테스트로 확인합니다.

```bash
python -m pytest tests/test_runtime_model_metadata.py tests/test_index_mode_defaults.py -q
bash -n ops/bin/insurance-rag-desktop-launcher
```

전체 회귀 검증은 다음 명령을 사용합니다.

```bash
python -m pytest -q
```

`src/ui/streamlit_app.py`는 과거 검증용 경로입니다. 현재 운영 및 신규 기능의 기준은 FastAPI + 정적 SPA입니다.
